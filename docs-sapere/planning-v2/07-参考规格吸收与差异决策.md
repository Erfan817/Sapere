> 版本：v2.1；日期：2026-11-18；作者：Monday。  
> 输入：`REBUILD-SPEC.md`。  
> 目的：明确哪些结构被吸收、哪些被改写、哪些不进入 Sapere，防止“读完规格但文档仍各说各话”。

## 2. 吸收后的产品骨架

参考规格的功能域可以整理为 Sapere 的四层：

```text
应用外壳
  ├─ 窗口、托盘、单实例、启动、快捷键、主题、更新、备份
内容层
  ├─ 空间、文档、笔记、会话、消息、任务、产出、回收站
智能层
  ├─ Chat、Agent、工具、审批、子 Agent、Skills、MCP、记忆
知识与媒体
  ├─ Wiki、知识库、PDF/OCR、媒体、翻译、生成任务、实时 ASR
```

Sapere 在其上增加：

```text
业务层
  ├─ Learning：资料、课程、题目、作答、提示、FSRS
  ├─ Work：CSV、白名单分析、可复算报告
  └─ Creation：作品、章节、设定、提案、版本
```

四层不是四套独立应用。所有层共享空间、权限、运行、版本、产出和诊断，但正式业务提交仍由各自领域服务负责。

## 3. 明确不照搬

| 项目 | 不照搬原因 | Sapere 做法 |
| --- | --- | --- |
| Vue 3 | 当前项目已建立 React/CodeMirror/E2E 链，重写收益低且会回归 | React 19 + 现有组件和主题 |
| `better-sqlite3` | S0 实测 Electron 45 V8/ABI 编译失败；ADR-001 已记录替代 | `node:sqlite`，保留可替换端口 |
| Renderer 分组 `db:*` CRUD | 会让页面绕过版本、审批、路径和业务规则 | 领域命令 + Backend 单写者 |
| `<域>:<动作>` IPC 字符串 | 参考规格和 BRIEF 均要求可枚举的域动作命名 | `domain:action` + `sapere:` 传输前缀 |
| 约 90 个内置技能 | 内容有版权，且数量不等于能力 | 自写少量样板技能，先验证格式和权限 |
| 424 条通道/86 条路由 | 参考程序规模不是产品目标 | 以 v0.2 的信息架构和真实任务驱动 |
| 20/21 张表、约 90 个技能包 | 表数和技能数不是能力证明 | 只建实际使用的表；首批技能内容自写 |
| 内置整套 Python | 项目当前为 Node/TypeScript，CSV 可先确定性执行 | 可选 Python 环境后移，非启动前置 |
| 微信桥/本地网关作为核心 | 会打开端口、接触外部账号，风险和维护成本高 | v1.0 可选、默认关闭、独立风险说明 |
| 自动更新作为首版前提 | 签名、更新源、回退链尚未具备 | 先手动更新和明确签名状态，后续验证自动更新 |
| 参考程序的主进程单文件 bundle | 可读性、调试和维护差 | 按域拆源，最终构建时再 bundle |
| 参考程序的品牌/图标/文案 | 不能复用其品牌素材 | 使用 Sapere 品牌资产和自写文案 |

## 4. 参考规格待定问题的决策

### 4.1 设置落库

**决定**：应用/业务设置统一进 `settings` 或对应业务表；localStorage 只保存纯 UI 小状态（面板宽度、折叠、最近 tab）。密钥只存 Main Vault。

**理由**：设置跨重启、可备份、可诊断、可在主进程使用；把关键偏好放在 Renderer 会导致 Backend/Agent 读不到或状态分裂。

### 4.2 路由与协议

**决定**：目标生产环境使用受控自定义协议（建议 `sapere://`）+ history 路由；开发态使用明确的本机 Vite URL。

**理由**：避免为了 `file://` 工作而放宽权限，也便于 CSP、来源校验和未来跨平台。

### 4.3 主进程打包

**决定**：源码按域拆分，构建产物可 bundle；不以参考程序的 5 MB 单文件 `main.js` 作为结构目标。

**理由**：可审查、可测试和可定位错误；最终体积由构建结果测量，不用单文件形态证明能力。

### 4.4 网关、微信、实时语音

**决定**：v1.0 前仅作为可选模块；默认关闭；启用时单独解释端口、账号、音频和外部数据风险。

**理由**：它们不是学习/工作/创作闭环的必要条件，且会扩大安全面和发布矩阵。

### 4.5 数据库与 native 模块

**决定**：v2 不把 `better-sqlite3` 作为必需依赖；`node:sqlite` 已有开发/打包证据。若未来需要，另立 ADR 并做 Electron ABI、asar unpack 和回滚验证。

**理由**：不能把已经失败的 native 链重新写回“必须照做”，也不能让安装包依赖开发机残留。

### 4.6 IPC 形状

**决定**：

- 页面侧只出现类型化函数，不出现动态 channel。
- 逻辑命令登记在 `packages/contracts` 与本文。
- Backend/Agent 的跨进程消息是内部协议，不直接暴露给 Renderer。
- 不向页面开放 `db:*` CRUD。

**理由**：参考规格的“通道表是接口真相”是正确的；具体语法应服务当前安全模型和代码。

## 6. 需要新 ADR 的事项

以下事项不能只在本文写一句，必须在实施前形成 ADR：

1. 请求信封从扁平 schema 升级到带 `protocolVersion/requestId` 的过渡方案。
2. 生产自定义协议、CSP 和 Electron fuses 的最终组合。
3. 文档工作副本与不可变修订的冲突/恢复协议。
4. MCP stdio 的进程、环境、权限和退出所有权。
5. 完整应用备份是否包含 checkpoint，以及恢复后的旧审批处理。
6. 本地网关、微信桥和实时语音的默认关闭与风险提示。
7. 第三方技能/工具/主题的信任、签名和分发策略。

本次已先创建 [ADR-004](../../docs/adr/ADR-004-s0-5-workbench-conventions-and-service-boundaries.md)，记录 S0.5、12 服务边界和 P0–P3 顺序；其余事项仍待专项决策。

## 7. 参考规格不可作为完成证据

以下结论只说明“参考程序曾这样做”，不能说明 Sapere 已实现：

- 原程序有 424 条通道或 86 条路由。
- 原程序有 90 个技能包。
- 原程序有本地网关、微信桥、实时语音。
- 原程序打包体积、路由数量或页面布局。
- 原程序的功能列表、数据表和 UI 截图。

Sapere 的完成证据必须来自本项目当前构建、当前锁文件、当前设备/安装环境、实际输入和实际结果。

## 8. 吸收结论

v2 吸收参考规格的工作台骨架、接口纪律、安全原则、运行/审批/恢复思想、文件与备份结构、能力包格式和交互范式；拒绝照搬品牌、Vue、`better-sqlite3`、裸 DB 桥、技能内容和不可控的外部桥接。

最重要的产品差异是：**Sapere 不只是“通用 AI 工作台”，而是让学习、CSV 工作和持续创作三类任务各自形成可核对的本地闭环。** 平台能力为这三类任务服务，而不是替代它们。
