# Sapere 桌面架构与数据设计 v2

> 版本：v2.1；日期：2026-11-18；作者：Monday。  
> 性质：在现有 S0 骨架之上的目标架构；不表示 v0.2 数据表和页面已经全部存在。  
> 已验证事实：Electron Main、sandbox Renderer、Backend/Agent utilityProcess、`node:sqlite`、独立 checkpoint 库和最小 NSIS 包已在 S0 实际运行。  
> 关联：[Agent 架构](02-Agent架构与技术决策.md)、[工程交付](04-里程碑与工程交付.md)、[IPC 与数据契约](06-IPC与数据契约.md)。

## 1. 架构目标

1. 正式内容和业务事实在本地，模型、搜索、OCR、语音等外部服务可替换。
2. 每个业务对象只有一个明确写者；页面、Agent 和扩展不能绕开领域服务直接改库。
3. 文件系统与 SQLite 不假装天然同事务，通过不可变修订、staging、操作日志和恢复记录协调。
4. 长任务、流、审批、取消和恢复可观察，失败不静默。
5. 新增页面、命令、事件、表或文件先登记，再实现。
6. 安全默认收紧；用户不需要为了日常使用关闭 Renderer 沙箱或开启任意脚本。
7. 业务内核优先于平台堆叠；v0.2 未稳定前不把 Wiki、媒体、MCP 等作为隐性前置。

## 2. 当前实现与目标的关系

### 2.1 已有

- `apps/desktop/src/main`：窗口、单实例、模型网关、模型设置、worker 监督和 IPC。
- `apps/desktop/src/preload`：只暴露 `window.sapere.request`、`subscribe` 和只读命令清单。
- `apps/desktop/src/renderer`：三空间文档、对话/助手、工作台、设置、修改审阅。
- `packages/contracts`：Zod 请求 schema、类型和错误。
- `packages/backend`：`node:sqlite` 业务库、迁移、文档修订和 FTS5 trigram 样例。
- `packages/agent-runtime`：LangGraph worker 与自有 SQLite saver。
- `packages/editor`：CodeMirror 适配。
- `tests`、`scripts`：单元、真实 Electron E2E、版本/许可/发布辅助。

### 2.2 尚未存在

- 真正的多文档/多空间数据模型、笔记、会话、Agent 运行、任务、产出、回收站、Wiki、知识库、技能、工具/MCP 和媒体表。
- 统一的命令/事件注册表、数据库数据字典、迁移快照与恢复演练。
- 打包后的安全 fuses 加固、生产自定义协议、完整 CSP 和所有路径边界测试。
- Job Worker、文件索引、备份功能和自动更新。

v0.2 的实现顺序以 [04](04-里程碑与工程交付.md) 为准，不因本文画了完整目标就跳过 S0 退出条件。

## 3. 进程职责

```text
┌──────────────────────────── Electron Main ─────────────────────────────┐
│ app lifecycle / BrowserWindow / tray / menu / shortcut / dialog       │
│ single instance / close guard / protocol / permission policy          │
│ SecretVault / ModelGateway / ToolBroker / Supervisor                  │
└───────────────┬──────────────────────────────┬────────────────────────┘
                │                              │
     ┌──────────▼──────────┐        ┌──────────▼──────────┐
     │ Backend utilityProc │        │ Agent utilityProc   │
     │ domain services     │        │ LangGraph runtime   │
     │ business.sqlite     │        │ checkpoints.sqlite  │
     │ file commits        │        │ tools / approvals   │
     │ migrations/indexes  │        │ stream / recovery   │
     └──────────┬──────────┘        └──────────┬──────────┘
                │                              │
     ┌──────────▼──────────┐        ┌──────────▼──────────┐
     │ Job Worker (on-demand)│       │ Model provider(s)   │
     │ PDF / CSV / render    │       │ via Main Gateway    │
     └───────────────────────┘       └─────────────────────┘
```

| 部分 | 负责 | 禁止 |
| --- | --- | --- |
| Renderer | 页面、编辑器、结果显示、用户操作 | Node、文件系统、SQL、Key、任意 IPC |
| preload | 固定函数、request/subscribe、移除监听 | 暴露 `ipcRenderer`、shell、fs 或动态通道 |
| Main | 窗口、系统集成、监督、密钥、模型网关、ToolBroker、权限策略 | 启动时同步执行重计算或业务事务 |
| Backend | 领域服务、业务库唯一写者、迁移、文件提交、备份、索引 | 接受模型任意 SQL/路径/命令 |
| Agent | 图、工具循环、上下文、事件、checkpoint | 直接写业务库、读 Key、自由遍历工作区 |
| Job Worker | 受限解析、CSV、预览、重任务 | 获取未声明环境、任意 shell、写正式表 |

`utilityProcess` 提供进程隔离，不是操作系统级恶意代码沙箱。第三方技能、MCP 服务器或未来的任意代码执行需要单独信任和隔离设计。

### 3.1 12 个服务域

后台按 12 个服务域组织，不把所有能力塞进 Main 或单个 domain 文件：

| 域 | 首批职责 | 所属阶段 |
| --- | --- | --- |
| AI | Chat/Agent/run/approval/tool | S2–S3 |
| 数据 | spaces/docs/convs/msgs/tasks/outputs | S1–S3 |
| 文件 | 读写、导出、路径校验 | S1–S2 |
| 工作区 | 选择、迁移、备份 | S1 |
| 环境 | 可选 Python/venv | S7 |
| 文档 | PDF/OCR/Office | S5 |
| 媒体 | 音视频、转写、帧、翻译 | S5/S7 |
| 知识 | Wiki/KB/webImport | S5 |
| 扩展 | Skill/Tool/MCP | S6 |
| 外观 | 主题、令牌、快捷键 | S1/S6 |
| 外壳 | 窗口、托盘、启动、更新、日志 | S1/S8 |
| 对外 | 本地网关、微信桥 | S8 可选 |

每个域由“注册层 + 业务层”组成。注册层只做来源、schema、权限和路由；业务层不 import Electron 窗口对象。跨域通过领域命令或端口，不直接改别人的表。

## 4. 安全边界

### 4.1 必须保持的 BrowserWindow 配置

```ts
webPreferences: {
  contextIsolation: true,
  nodeIntegration: false,
  sandbox: true,
  webSecurity: true,
  preload: /* 固定文件 */,
}
```

同时：

- 拒绝 `window.open`、外部页面导航、权限请求和未登记协议。
- Renderer 只能加载构建产物；开发态只允许明确的本机 Vite 地址。
- 生产页面优先使用自定义 `sapere://` 协议或等价受控协议，不用放宽 `file://` 权限解决路由。
- 所有 IPC 校验发送 frame 必须为主窗口主 frame，且 URL 符合允许来源。
- CSP 禁止任意远程脚本、危险内联和未声明连接；需要外部内容时使用文字或隔离预览。

### 4.2 Electron fuses

发布版必须显式设置并验证以下目标值：

| fuse | 目标 |
| --- | --- |
| `RunAsNode` | disabled |
| `EnableCookieEncryption` | enabled |
| `EnableNodeOptionsEnvironmentVariable` | disabled |
| `EnableNodeCliInspectArguments` | disabled |
| `EnableEmbeddedAsarIntegrityValidation` | enabled |
| `OnlyLoadAppFromAsar` | enabled |
| `LoadBrowserProcessSpecificV8Snapshot` | 按实际打包方案确认，不能留下未知 |
| 其他与 file 协议额外权限相关的选项 | 按锁定 Electron 版本检查并收紧 |

当前包尚未完成 fuses 加固；它是 v0.2 发布阻断，不是 v2 完成后的优化项。

### 4.3 路径

- 所有文件参数必须是对象 ID 或工作区相对逻辑路径，不接受模型/页面提供的任意绝对路径。
- Backend 解析真实对象归属，再做规范化、realpath、软链接/junction/reparse point 检查。
- 目标必须位于当前工作区允许根；导出到用户选择位置需显式对话框确认。
- 写入采用临时文件、哈希校验和原子替换；跨目录移动使用同一文件系统的 staging。
- 不把字符串 `startsWith(root)` 当成完整路径防护。

### 4.4 密钥与日志

- Key 只进入 Main 的系统保护存储；Renderer、Agent、checkpoint、项目包和普通日志不获得明文。
- 子进程环境由白名单构造，不继承 `*_API_KEY`、`LANGSMITH_*`、`NODE_OPTIONS` 或 inspect 参数。
- 日志记录错误码、trace/run ID、版本和时间；默认不记录正文、Key、认证头和完整请求。
- 诊断导出先脱敏，由用户选择是否包含特定文件。

## 5. IPC 与接口纪律

### 5.1 传输

当前传输：

- 请求：`sapere:request`，Promise 返回 `{ok:true,data}` 或 `{ok:false,code,message}`。
- 事件：`sapere:event`，通过 `subscribe` 返回取消函数。

命令身份采用 `domain:action`，例如：

```text
document:read
document:save
conversation:create
chat:send
agent:start
agent:approvalRespond
workspace:migrate
```

`REBUILD-SPEC` 使用 `<域>:<动作>` 的命名。Sapere 采用同一语法，传输通道仍统一为 `sapere:request` / `sapere:event`；命令清单由 `packages/contracts/commands.ts` 提供，`pnpm channels` 可直接打印。

### 5.2 不允许的桥

- 不暴露 `ipcRenderer.on/off/send/invoke` 原对象。
- 不提供任意 `invoke(channel, args)`。
- 不向 Renderer 暴露通用 `db:*` CRUD、SQL、文件系统或 shell。
- 新增命令必须进入 [06](06-IPC与数据契约.md) 和 `packages/contracts` 的 schema；未登记命令必须拒绝。

### 5.3 请求信封

目标信封：

```ts
type Request<T> = {
  protocolVersion: 2;
  requestId: string;
  type: string;
  payload: T;
};
```

v0.2 可在现有扁平 schema 上渐进扩展，但必须保留请求 ID、schema 版本、超时和稳定错误码。响应应包含 `traceId` 和可重试性。

### 5.4 事件

- 事件名用过去式：`started`、`delta`、`completed`、`failed`、`cancelled`。
- 事件包含 `eventId`、`seq`、`type`、时间、`runId`（适用时）。
- 高频 token 可合并；工具、审批、状态、产物和错误必须持久化后可重建。
- 订阅必须可释放；页面反复进入不叠加监听。

## 7. 工作区与文件布局

用户首次启动选择内容工作区；系统 userData 仅保存工作区登记、UI 偏好和加密凭据。安装目录不保存可变正文。

数据库只保存相对工作区根的逻辑路径或对象 ID；绝对路径只保留在运行时配置和诊断摘要中，不能进入可迁移的业务记录。

```text
<用户选择的 workspace>/
├─ .sapere/
│  ├─ workspace.json              工作区格式、ID、版本
│  ├─ business.sqlite             Backend 独占写入
│  ├─ business.pre-vN.sqlite      迁移前快照（按策略保留）
│  ├─ agent/checkpoints.sqlite    Agent 独占
│  ├─ staging/                    未完成导入/导出/文件提交
│  ├─ journals/                   跨文件与数据库操作恢复记录
│  ├─ indexes/                    可重建全文/向量/缩略图索引
│  ├─ logs/                       脱敏日志与轮转
│  └─ cache/                      可清理缓存
├─ spaces/<spaceId>/
│  ├─ sources/<sourceId>/         原件与不可变源版本
│  ├─ documents/                  Markdown 工作副本
│  ├─ revisions/                  不可变正文修订对象
│  ├─ attachments/                图片等附件
│  └─ artifacts/                  报告、CSV、DOCX、PPTX、转录
└─ outputs/                       全局“最近产出”视图的索引目标或空间产出汇总
```

正式真源是“业务数据库中的对象/修订指针 + 不可变内容对象”。可读 Markdown 工作副本用于查看和外部编辑；外部改动需经冲突协调形成新修订，不能默默修改 head。

| 组 | 表 | 关键不变量 |

### 8.4 数据铁律

1. 可变业务表必须有 `createdAt / updatedAt / deletedAt`；删除进 `trash`，恢复保留原 ID，彻底删除才释放文件。
2. 业务库只存相对路径或对象 ID；工作区迁移时不能依赖绝对路径。
3. `settings`/业务设置表保存可恢复配置；localStorage 只存面板宽度、折叠、选中项等 UI 瞬态；Key 只存 Main Vault。

## 9. 文档保存协议

文件与数据库不能形成单个原生事务。保存按以下步骤：

1. Renderer 提交 `document:save`，带 `documentId`、内容和 `baseRevision`。
2. Backend 校验空间、对象、逻辑路径、长度和 revision。
3. 将候选内容写入 `staging/`，计算哈希。
4. 在 `revisions/` 写入不可变内容对象；失败不更新 head。
5. 在业务事务中写 `document_revisions`、更新 `documents.head_revision_id`、写保存事件和幂等结果。
6. 更新可读工作副本；若发现外部编辑，保留冲突副本并返回冲突状态。
7. 进程崩溃后由 journal 清理孤立对象、补齐已提交工作副本，不删除仍被历史或备份引用的内容。

UI 的“已保存”只以 Backend 返回的已提交修订为准。编辑器内未保存文字保留在 Renderer；持久层失效时提供复制/另存恢复出口，不承诺所有未确认输入一定能恢复。

## 10. 迁移

- 使用 `PRAGMA user_version` 和顺序迁移脚本；单写者执行，迁移前做可恢复快照。
- 每次迁移有版本、校验、前向说明和失败回滚；迁移失败不在半库上继续工作。
- 新程序可读旧 schema；旧程序遇到更高 schema 拒绝写入。
- 数据回退不等于替换 EXE，需要匹配的快照或经过验证的向下迁移。
- 迁移和备份结果要进入发布证据；不能只以“应用能启动”判断成功。

## 11. 搜索与索引

- v0.2 使用 SQLite FTS5 或等价本地全文索引，按空间过滤；S0 已用 trigram 验证中文短句。
- 索引是派生数据，可重建；重建不修改源件、修订、作答或作品。
- 文件改名/删除、源修订和文档回退后同步更新索引状态。
- 向量检索、知识图谱和外部语义检索保留为独立端口，不进入 v0.2 必需路径。
- 上下文包记录实际读取的片段，不能把“检索到几段”当作“已读完整资料”。

## 12. 备份与恢复

### 12.1 两类备份

| 类型 | 包含 | 不包含 | 用途 |
| --- | --- | --- | --- |
| 空间/项目导出 | 空间业务记录、文档、来源、修订、附件、产物、manifest | Key、登录态、缓存、checkpoint、其他空间 | 分享、迁移、局部恢复 |
| 完整应用备份 | 所有工作区业务数据、设置和必要文件 | Key、浏览器状态、可重建缓存、可选 checkpoint | 设备迁移或整机恢复 |

### 12.2 恢复

1. 暂停会写业务数据的新 run 和导入。
2. Backend 获取维护租约，等待提交屏障；Agent 在安全点停止或标记中断。
3. SQLite 使用受支持的备份/快照路径，不直接复制带 WAL 的活跃库。
4. 在 staging 校验 manifest、版本、空间、文件哈希、路径和压缩膨胀。
5. 全部通过后恢复到新目录并登记；拒绝路径穿越、链接逃逸和不兼容版本。
6. 重建索引，核对文档、来源、作答、复习、任务和产物关系；原目录保留。

恢复的是业务数据，不是正在运行的 Agent 逐步复活。checkpoint 不在普通项目包中；恢复后的旧审批和旧 run 必须重新校验。

## 13. 日志、监控与诊断

- 日志按日期轮转，可按保留天数清理；关键事件同时有业务记录。
- 错误包含稳定错误码、用户可读原因、下一步、trace/run ID；技术堆栈只进诊断。
- 进程异常不无限自动重启；用户可见重连，编辑内容保留。
- 关闭先请求 shutdown，有界超时后强制回收；避免孤儿 utilityProcess、MCP stdio 或 Job Worker。
- 诊断包默认不含正文、Key、认证头和完整请求；用户选择后才加入特定文件。

## 14. 扩展点

| 扩展 | 入口 | 信任等级 |
| --- | --- | --- |
| 核心业务模块 | 编译时注册，领域命令 | 自有受信代码 |
| 内容/课程/模板包 | schema 校验、哈希、路径检查 | 内容不可执行 |
| Skill | `SKILL.md` + 资源，权限由 Broker 决定 | 首版仅随包可信；导入后逐项验证 |
| Tool/MCP | ToolRegistry + MCP adapter | 外部能力，显式启用和审批 |
| 编辑器/文件类型 | 预览/编辑/导出适配器 | 需数据和安全测试 |
| 外部运行器/工作流 | 通过 Run/Approval/Artifact 端口 | 不直接写业务库 |

新增扩展不得改变正式内容、审批、密钥和路径规则。第三方代码执行、市场安装和服务端任务需要新 ADR。

## 15. 与参考规格的工程差异

| 主题 | 参考规格 | Sapere v2 | 原因 |
| --- | --- | --- | --- |
| UI 框架 | Vue 3 | React 19 | 当前实现、测试和编辑器链已建立 |
| SQLite 驱动 | `better-sqlite3` | `node:sqlite` | S0 实测 better-sqlite3 V8 编译失败；ADR-001 已有替代证据 |
| IPC 命名 | `<域>:<动作>` | `<域>:<动作>` + `sapere:` 传输前缀 | 与参考规格一致，保留登记和校验原则 |
| DB 桥 | 可分组 CRUD | 不向 Renderer 暴露通用 CRUD | 防止绕过领域服务、审批和版本 |
| 页面数量 | 86 条主干路由 | 按 v0.2 核心信息架构逐步增加 | 不追求数量，不制造空页面 |
| 打包 | 主进程单 bundle | 按域拆源，构建时 bundle | 可维护性和测试优先 |
| 更新 | 自动更新组件 | 先手动更新，后接经过验证的自动更新 | 签名、回退和发布链未完成 |
| 网关/微信 | 平台能力 | v1.0 可选，默认关闭 | 会打开端口/外部账号，不能成为核心前置 |
