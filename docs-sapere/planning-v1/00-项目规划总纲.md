## 1. 项目摘要

Sapere 为用户提供持续的项目工作空间，把资料、文档、任务、Agent 和成果关联起来。用户可以只学习一份材料、独立完成一次办公分析，或从空白开始创作作品；也可以让三种活动在同一项目中接续。

产品的共同流程为：建立/继续项目 → 加入资料或创建内容 → 阅读、练习、执行或制作 → 审阅结果 → 保存版本 → 导出或下次继续。各方向保持独立业务状态，作品无需课程前置，工作无需学习前置。

本项目同时服务真实使用和求职展示。工程内容应能被演示、解释、修改、测量和追溯；成熟组件与 AI 辅助开发如实记录，简历只描述实际完成且能说明的贡献。

## 4. 用户、价值与评价目标

首批由项目发起人本人使用，再邀请少量有类似任务的中文试用用户。技术自学、个人数据整理、文章与小说开头是首版样例，不代表未来只服务这些学科或作品形式。

| 用户任务 | 主要痛点 | Sapere 的帮助 | 可以验证的结果 |
| --- | --- | --- | --- |
| 学习课程和个人资料 | 看懂解释却不清楚会不会；记录散落 | 原文与问答、独立练习、提示记录和到期复习 | 作答/提示/评分真实保留，跨日继续 |
| 研究或处理工作文件 | 数据、分析过程、解释和成果分开 | Agent 组织任务，确定性工具计算，生成可核对报告 | 结果可复算、文件可带走、失败可查 |
| 持续创作 | 上下文反复解释，改稿容易丢版本 | 作品/章节/设定、上下文选择、AI 审阅和恢复 | 无学习前置即可完成作品并继续修稿 |
| 跨日使用 | 重启后找不到现场和下一步 | 项目、文件、运行、版本和个人记录关联 | 打开可继续，备份可恢复 |

质量评价采用实际任务完成、保存/恢复正确性、引用可核对、结果可重算和跨日接续。消息数量、字数、功能数量、星数与停留时长可供分析，但不能单独证明学习效果或产品价值。

## 5. v0.1.0 产品基线

### 5.1 共同基础

- 独立安装、应用身份和用户数据；单个活动工作区、多个项目，项目可归档和恢复。
- MD/TXT、文字 PDF 与 CSV 导入，原件版本、阅读、笔记和项目内搜索。
- 文件树、多标签、可收起 Agent 面板、任务中心、模型与数据设置。
- 自动保存状态、冲突处理、文档修订、回收站、导出及项目逻辑备份/恢复。
- 有界任务、工具范围、审批、取消、失败、中断恢复、阶段产物和用量记录。
- 无模型时本地阅读、编辑、固定题作答、复习、已有分析重算和导出可用。

### 5.2 三条独立流程

| 方向 | v0.1.0 的完整小流程 | 关键结果 |
| --- | --- | --- |
| 学习 | 导入课程/资料 → 阅读/有来源提问 → 固定题或确认后的 AI 题 → 作答反馈 → 复习 | 题目快照、提示/看答案记录、复习调度，支持跨日 |
| 工作 | 导入 CSV → 核对类型与缺失值 → 指定分析计划 → 确定性计算 → 报告与结果导出 | 输入哈希、参数、执行与指标对应，可复算 |
| 创作 | 空白/导入 → 单篇或章节组织 → 设定/资料选择 → AI 提案/修改 → 版本恢复 → 导出 | 编辑器中可接续的正式内容与可追溯修改 |

首版自动应用默认关闭；用户可按一次任务选择在限定文档/操作范围内自动应用并留快照。它不自动授予跨项目访问、任意代码执行、外部发送或发布权。

### 5.3 范围外能力怎样保留

## 6. Agent 框架方案

截图可以作为概念入口，正式职责按以下安排：

| 层 | 选择 | 在 Sapere 中负责 |
| --- | --- | --- |
| 桌面运行 | Electron / Node | 进程、窗口、系统集成和本地文件；这层不同于 Agent 图运行时 |
| Agent Runtime / 编排 | LangGraph JS | 图状态、运行检查点、暂停/恢复、事件与明确步骤 |
| Agent Framework / 高层入口 | LangChain JS | 模型与工具适配、消息、结构化输出、`createAgent` 循环 |
| Harness / 复杂任务入口 | Deep Agents JS | 规划、虚拟文件上下文、Skills、子任务和长任务组织，验证后按 profile 启用 |
| 业务能力 | Sapere 自有领域服务 | 项目、资料、真实作答、确定性计算、作品修订、授权和成果保存 |

LangChain 的 `createAgent` 已基于 LangGraph；Deep Agents 也建立在这套生态之上。一次任务可以选普通 Agent 或 Deep Agents profile，不必机械执行三个独立 Agent 循环。

**初始决策：** LangChain/LangGraph 是默认执行基础；S0 核依赖和持久化，S3 在真实工具、范围、取消和恢复链就绪后比较 Deep Agents 的受控资料研究 profile。不合适则保留接口，默认任务仍可交付。

LLM 负责解释、计划和候选内容；业务服务负责真事实和正式提交。例如计算结果来自实际执行，作答来自用户提交，版本来自文档服务。Agent checkpoint 能帮助继续执行，不替代业务库、文件备份或事务。

## 7. 桌面总体架构

采用应用内部模块化，不以云服务为首版前提：

```text
React Renderer：阅读 / 编辑 / 学习 / 工作 / 创作 / 任务中心
        │ 窄 preload API
Electron Main：窗口、系统对话框、进程监督、凭据与模型网关
        ├─ Backend utilityProcess
        │    项目 / 资料 / 文档 / 学习 / 工作 / 创作领域服务
        │    business.sqlite 唯一写入者 + 文件/版本提交
        ├─ Agent utilityProcess
        │    LangChain / LangGraph / Deep Agents profile
        │    独立 checkpoint；工具写入经业务接口
        └─ 按需 Job Worker
             PDF 解析 / 受限 CSV 运算等重任务
```

Main 不运行同步数据库事务和重解析，Renderer 不获得 Node 或模型 Key。业务命令和 Agent 调用通过校验的接口通信；独立进程有利于隔离崩溃，但不等于可信任任意脚本的 OS 沙箱。

| 共同对象 | 设计重点 |
| --- | --- |
| 项目 | 三用途可共存，归属和范围清楚 |
| 资料 / 源修订 | 来源、哈希、格式和版本；引用定位到页/片段 |
| 文档 / 正文修订 | 自动保存、条件提交、冲突、历史和恢复 |
| 任务 / run / 审批 / effect | 可观察、取消、恢复，防重复提交与副作用 |
| 作答 / 复习 | 题目快照、提示、评分方式和调度日志 |
| 数据集 / 分析 | 输入版本、结构化规则、实际结果和可复算信息 |
| 作品 / 章节 / 设定 | 稳定身份、顺序、上下文和导出 |
| 产物 / 上下文包 | 与输入、运行、版本、模型及消耗关联 |

每一类对象只有明确的写入服务；搜索与向量索引属于可重建派生数据。业务数据、正文文件、执行 checkpoint 和密钥配置分层保存，迁移与备份分别定义。

## 8. 可扩展性与工程原则

1. **按领域建模块**：学习、工作、创作共用项目/资料/版本，不共享一张含义混乱的“万能记录表”。
2. **工具经业务接口**：模型不能直接发任意 SQL 或绕过文档保存服务；技能也不能覆盖权限。
3. **状态和范围可见**：实际模型输入、工具可读范围、修改目标、版本和预算相互一致。
4. **保存和恢复先有契约**：文件与数据库不假装天然同事务，用不可变修订、条件提交和恢复记录协调。
5. **扩展按类型注册**：业务模块、内容包、Skill、工具、编辑器和外部执行器各有接口，不全叫插件。
6. **先单机可靠，再扩展部署**：专业 Python/媒体工具可独立进程；团队、云任务和同步后续按实际需求增加。
7. **用户界面面向任务**：框架、token、MCP、checkpoint 等技术信息放设置/诊断或必要的运行详情，不让用户先懂框架才能做事。
8. **依赖可追溯**：明确库版本、原生 ABI、资产来源和升级策略；不为追流行同时叠多套运行时。

## 10. 质量、数据保护与发布管理

### 10.1 验证层次

- 纯规则：客观评分、调度、CSV 计算、状态、幂等与修订条件。
- 真实集成：SQLite、文件、迁移、进程、模型适配、工具和备份恢复。
- 真实 Electron：实际窗口中完成关键流程，至少一次发行候选安装包验收。
- 人工专项：中文 IME、100%/125%/150% 缩放、键盘/可见焦点、PDF 引用、长稿和模型输出质量。
- 故障与升级：断网、取消、强杀、保存失败、损坏项目包、迁移失败、版本回退和独立目录恢复。

Mock 用于稳定回归，不能替代真实模型、真实桌面或打包环境验证。本轮仅写规划，不把这些要求标记为已通过。

### 10.2 保护与可恢复性

API Key 使用系统保护方案，不进入渲染层、提示词、普通日志和项目包；外发上下文可见。文件访问按项目和对象 ID 检查，MCP/Skill/来源正文不得自动扩权。项目备份排除凭据和运行 checkpoint，恢复采用独立目录；应用升级前的敏感数据快照另行管理。

### 10.3 分发

首发必交 Windows NSIS 安装包，便携包为可选发行物；若发布则明确数据位置并单独验收。初始手动更新，未来再接入经过验证的签名更新。未签名测试包如实说明；稳定发行的签名安排需实际决定，不能宣称已签名。

schema、项目包、工具协议与 checkpoint 各有版本。软件回退要判断数据兼容，不能只替换 EXE。发行有提交、锁文件、安装包哈希、版本说明、已知限制与恢复记录。

| --- | --- | --- |
| 框架名词堆叠 | 三套循环重复规划，状态和费用难归属 | 统一 run 接口；普通/复杂 profile 比较后启用 |
| 原生/Node 不兼容 | 开发可用，utilityProcess 或发行包崩溃 | S0 核内嵌 Node、SQLite ABI 和版本组合，通过前不扩业务 |
| 丢内容 / 重复副作用 | 错误已保存、重试重复作答、取消后仍改稿 | 发布阻断；以条件提交、效果账本、故障注入验证 |
| 模型结论替代真实结果 | 假引用、模型心算、画像冒充掌握 | 来源校验、实际计算、真实行为与建议分开 |
| 三方向同时范围失控 | 专业 Office、媒体或市场变成首版隐性前置 | 保留长期能力，但变更版本范围和估算，不暗加承诺 |
| 个人维护超出能力 | 无法解释运行和失败、过度依赖生成代码 | 边实现边记录决策、调试和失败，阶段演示与学习同步 |
| 求职描述失真 | 把规划、依赖、未跑过的数据写成自研成果 | 简历逐项对应真实实现、职责、验证与来源 |

建议开工后的首个评审是 S0 退出：框架已锁定、进程/持久化可跑、编辑器和最小发行路径有结果。若存在不兼容，先解决或形成替代 ADR，不用内存/浏览器演示代替桌面验证。

## 12. 项目证据与简历准备

按实际工作保留：需求与原型、ADR、数据模型、关键代码与评审、测试/恢复记录、发布说明、录屏和失败复盘。个人项目用自己的 Issue/PR 管理也有价值，不虚构团队成员、商业用户、实习、奖项或营收。

优先形成能深入讲的技术问题：

- Agent 为什么分进程，取消和恢复怎样发生；thread、run、checkpoint 为什么分开。
- 什么内容算已保存，数据库和文件中途失败怎样恢复。
- 资料更新后旧引用怎样解释，模型能访问哪些内容。
- 作答和提示怎样防重复记账，复习为何今天到期。
- 报告数字怎样复算，AI 参与哪一步而没有替代计算。
- AI 和用户同时改稿怎样处理冲突，如何采用和回退。
- 新工具、编辑器或业务模块怎样接入，需要改哪些地方。

这些是待实现的成果方向。性能、学习效果、用户量和完成度只有在实际测量后才写入简历；使用 AI 辅助开发如实记录，本人应逐步掌握所负责代码、设计、调试与验证。
