## 1. 发布目标与后续能力

`v0.1.0` 交付三个可验证的小闭环：

- 学习：导入资料或课程 → 有来源的提问 → 固定题或确认后的 AI 题 → 作答与提示记录 → 到期复习。
- 工作：导入 CSV → 明确计算规则 → 可复算的数据处理 → 输出 Markdown 报告与 CSV 结果，并能核对计算。
- 创作：空白或导入稿件 → 单篇或多章编辑 → 选择上下文 → AI 修改提案 → 审阅、版本恢复与导出。

没有模型或网络时，阅读、手动编辑、固定题作答、已有卡片复习、已有 CSV 分析配置重算、历史查看和导出继续可用。模型失败不能阻断本地内容保存。

进程职责按主架构落实：Electron Main 管理窗口、凭据、模型网关、IPC 路由与进程监督；Backend utilityProcess 承担领域服务并作为 `business.sqlite` 的唯一写者；Agent utilityProcess 执行 Agent 并持有独立 checkpoint 库。Checkpoint 不作为业务真源。重解析等任务可按需分进程；CSV 工作只执行白名单操作或结构化计算方案，首版不开放任意 Shell。

Office 深度编辑、扫描件 OCR、图像/音视频制作、自由多 Agent、云端任务、插件市场、多设备与团队协作进入后续能力库，按需求与前置条件逐项建设；这里不作永久排除。

版本建议：`0.1.0-alpha.N` 用于开发验证，`0.1.0-beta.N` 用于小范围试用，满足 S6 门槛后发布 `0.1.0`。版本号不代表学习效果或商业成熟度。

## 2. 估算口径与阶段依赖

假设一名主要开发者，每周投入 15–20 小时；包含设计、实现、评审、调试、文档和本阶段验收。使用 AI 辅助仍需保留理解、修改与核验时间。数字是初始估算，S0 完成后按真实吞吐重新估算。

| 阶段 | 主要结果 | 依赖 | 基础工时 | 退出门槛 |
| --- | --- | --- | --- | --- |
| S0 技术验证 | 固定框架版本；进程、持久化、编辑器和打包方案有证据 | 无 | 20–32 h | S0-01–S0-07 通过，失败项有替代方案 |
| S1 桌面与数据 | 应用壳、项目、本地数据、迁移和备份基础 | S0 | 28–44 h | 无模型可建项目、保存、重开，故障不静默吞掉 |
| S2 编辑与资料 | 文档编辑、资料导入、来源定位与搜索 | S1 | 32–48 h | 真文件可读写、可检索，引用能回原位置 |
| S3 Agent 横切 | 工具、上下文、任务、审批、取消和恢复 | S1；文件工具依赖 S2 | 36–56 h | 一条跨重启任务可继续，副作用不重复执行 |
| S4 三业务切片 | 学习、CSV 工作、文本创作各自跑通 | S2、S3 | 52–80 h | 三条场景分别验收，不要求互为前置 |
| S5 可靠性与 Beta | 故障恢复、性能、兼容、安装与发布候选 | S4 | 28–44 h | 发布阻断问题清零，干净 Windows 安装验收通过 |
| S6 真实试用与正式版 | 跨日使用、修订、恢复演练和发布证据 | S5 | 12–20 h | 核心场景真实使用通过，正式版检查表签收 |
| **基础合计** | — | — | **208–324 h** | 各阶段区间相加 |
| **25% 缓冲** | 上游变化、集成返工、打包和环境差异 | — | **52–81 h** | 不提前作为新功能预算 |
| **含缓冲总量** | — | — | **260–405 h** | — |

每周 15 小时约需 **18–27 周**；每周 20 小时约需 **13–21 周**，均按总工时向上取整。真实试用建议覆盖至少 14 个自然日，可以与问题修订交错进行；等待、考试周和外部服务故障可能延长日历时间。这不是工期承诺。

S4 估算分配：学习 18–28 h、CSV 工作 16–24 h、文本创作 18–28 h，合计 52–80 h。任一切片发现基础能力缺口，先回到对应阶段修正，不用复制第二套存储或 Agent 系统绕过。

以上工时以 NSIS 为必交发行链；可选 portable、完整 Deep Agents 专项扩展或其他新增格式若超出已有任务时间，应单独重估，不暗含在缓冲里。

## 3. 关键任务清单与验收标记

标记含义：`单元` 是确定性规则检查；`集成` 使用真实本地服务/数据库；`桌面` 操作真实 Electron 应用；`恢复` 注入异常或验证数据恢复；`人工` 审阅来源、质量与交互。完成任务必须留下命令、版本、结果或人工记录，不以“代码已提交”代替验收。

### S0：技术验证与版本锁定（7 项）

| 任务 | 交付 | 验收标记与通过条件 |
| --- | --- | --- |
| S0-01 | ADR、版本清单与锁文件策略 | `人工/集成`：开发 Node 与 Electron 内嵌 Node、包管理器、Agent、数据库、复习库和编辑器版本兼容且可追溯；核对 ts-fsrs 的 Node 下限、SQLite saver 的 native 驱动范围，不能盲装 latest 或强制覆盖 |

| S0-06 | 模型协议、工具返回和流式事件小样 | `集成`：至少一套实际可用服务可调用、取消、报错；模型能力缺失不伪装成功 |
| S0-07 | 最小安装包和依赖准备说明 | `桌面`：干净 Windows 能打开窗口与写本地文件；缺环境有明确说明，不依赖开发机残留 |

## 4. 每个任务的完成定义

完成必须同时满足：需求和边界有记录；代码通过类型/格式等既有工程检查；适当的单元或集成检查通过；涉及交互时在真实桌面操作；错误、取消和恢复路径有结果；文档与实际行为一致。

涉及模型的任务应同时保存：确定性回归夹具与少量实际模型验证。Mock 用于稳定复现，不代替实际协议、流式、工具返回、取消和费用信息检查；真实模型调用由验证人员触发并记录预算。

规划中的测试属于交付要求，本轮未创建或执行测试。后续“通过”记录需注明应用版本、依赖锁定版本、设备、步骤、预期、实际结果与证据路径；涉及私人内容或密钥的证据不放入公开仓库。

## 5. 质量矩阵与暂定性能目标

| 级别 | 重点 | 实际证据 |
| --- | --- | --- |
| 单元 | 评分规则、状态机、幂等键、版本检查、FSRS/时区、路径规则、CSV 数字计算 | 固定输入、边界样例、可复现失败；不写只重复实现步骤的断言 |
| 集成 | 真实 SQLite/文件系统/迁移/checkpointer/IPC/工具、事务与备份 | 真库和独立目录验证，涵盖重试、冲突和重启 |
| 真实 Electron E2E | 从入口完成阅读、作答、CSV 报告、章节修订及导出 | Playwright Electron 或等价真实应用驱动；至少一条使用发行候选安装包，不只测浏览器 mock |
| 人工专项 | 中文 IME、文件保真、125%/150% 缩放、键盘与读屏基础 | 录屏/检查表；支持格式用固定样例集逐一核对 |
| 恢复与发布 | 强杀、断网、损坏包、升级迁移、回退、干净机与卸载 | 前后内容/元数据一致性及失败诊断记录 |

暂定参考机：Windows 11 x64、4 核或以上 CPU、16 GB RAM、SSD、1080p 显示器；S0 记录实际型号和电源模式后校准。以下都是目标，不是测量结果：

- 无模型冷启动到可编辑页面中位数 ≤5 s；同时记录 P95 与首次启动差异。
- 单章 2 万中文字符的输入/选区响应 P95 ≤100 ms，中文 IME 连续输入和 AI 流式期间无丢字；按实际内容量另补长文压力样例。
- 停止生成后 2 s 内进入明确的取消状态；远端调用不能立即停止时仍须阻断本地后续写入并显示情况。
- 单项目 1,000 份短文档的本地全文查询 P95 ≤1 s；资料总字节数和索引构建时间一起记录。
- “已保存”仅在持久写入成功后显示；保存失败、运行异常、索引失败始终有可见状态与重试入口。

本地模型推理、云模型响应、PDF/OCR 和网络下载单独计时，不并入桌面本地响应指标；文件大小、页数与并发上限在 S0/S2 根据样例测得后写进支持说明。

## 6. CI、依赖与可观测性

- PR 基线：锁文件安装、类型检查、已有 lint/格式检查、纯逻辑单元及数据层集成。Linux runner 跑平台无关部分，不代表承诺 Linux 桌面版。
- Windows runner：验证原生模块、实际 Electron、关键 E2E 和安装包冒烟；耗时较长的完整恢复/打包矩阵放发布候选，避免每次文案改动重复打包。
- Node、Electron、Agent 包和运行依赖固定版本；模型与大型 runtime 按校验和缓存，普通单元测试不临时下载运行时或模型。
- 每个失败携带 `trace_id/run_id`、错误码、简洁中文原因和可执行下一步；技术堆栈留在诊断日志。不得把完整私人文档、密钥或认证信息直接写日志。
- Token、供应商返回量、估算费用和实际账单分开；未知字段保持未知。取消、失败和重试可能已有供应商消耗，不承诺“失败一定免费”。
- 保持轻量依赖/资产台账：包与版本、来源、许可/通知、用途、更新责任；课程、模板、字体、图片、模型权重分别登记。实现新功能时同步维护，发行时汇总 notices。

## 7. 安装、升级和回退

首发提供 NSIS 安装版，portable 作为可选交付；两者需明确 userData 与项目目录行为，避免便携版自动读取安装版资料。普通用户权限优先，升级前关闭所属进程，卸载默认保留用户内容。

初始版本采用手动下载/安装，设置页明确“自动更新未启用”；未来接入自动更新时再核验签名、更新源、版本防降级、完整性、失败恢复和发布渠道。没有证书的测试包明确标为未签名 Beta；公开稳定发布的签名安排必须有实际证据或明确决定，不能宣称已签名。

升级先生成一致快照，再运行前向迁移；迁移失败保留原库与恢复路径。回退需要同时判断旧程序能否读取新 schema，不能只换回旧 EXE。优先用前向修复；确需恢复旧版时，恢复升级前的程序与数据快照，并说明其后新增内容如何保留/导出。

项目备份应是文件与业务记录的一致快照，SQLite 活跃库通过受支持备份/快照路径处理，不直接复制一个可能缺 WAL 的数据库文件。配置、Key、浏览器登录、缓存和模型权重默认不进入普通项目包；用户自愿导出的敏感配置需单独提示和保护。

## 8. 主要风险与处置

| 风险 | 触发信号 | 处置 |
| --- | --- | --- |
| 依赖组合或持久化不兼容 | Agent 能跑但恢复失败，native 模块在发行包崩溃 | S0 阻断；锁版本、验证替代组件，记录 ADR 后重估 |
| 三条业务同时变大 | S4 出现专业 Office、全媒体或市场的隐藏前置 | 拆出依赖和下一发布切片；保留长期能力，不靠临时复制系统绕过 |
| 内容丢失或重复副作用 | 错误“已保存”、取消后写入、重试重复记录 | 发布阻断；先修事务、版本和恢复，再扩展能力 |
| 模型输出不可用 | 无效引用、坏 JSON、假统计、误评分 | 业务校验、来源核对、真实执行计算、人工确认和降级 |
| 实际学习与维护成本高于估算 | 连续两阶段明显超出上界 | 调整节奏与发布切片，缓冲用于返工；不压缩必要恢复和数据验收 |
| 运行和费用失控 | 子 Agent 循环、工具重试或后台未退出 | 限制轮数/时间/预算/并发；可停止，记录失败与未知消耗 |
| 简历描述超过实际贡献 | 规划、AI 辅助或第三方能力被写成独立完成 | 用实际实现、调试、评审和测量证据逐条校正，来源如实说明 |
