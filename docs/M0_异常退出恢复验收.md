# M0 异常退出恢复验收

日期：2026-11-14。环境：Windows 11 x64；Electron 30.5.1；Node 24.16.0。应用为开发构建（`pnpm run build:electron`），使用隔离的 `SAPERE_DEV_USER_DATA` 与中文工作区。

## 结论

**通过：在 6 次强制终止（`taskkill /T /F`）后，应用均能重新启动并恢复最后一次已保存的笔记；保存边界被强制终止时，恢复结果为完整的旧版本或新版本，没有截断内容；数据库完整性与外键检查通过，数据库路径与 Markdown 文件一致。**

强制终止发生在自动保存 debounce 窗口内时，尚未写盘的输入会丢失，这是当前 500ms 自动保存策略的预期边界。

## 场景与证据

证据：`.sapere/m0-abnormal/run-m2bl3P/report.json`，`success=true`，页面错误为空；只读数据库检查见同目录。共记录 6 次强制终止与 7 次启动。

1. **工作区创建未完成时终止**：在界面出现“重启后生效”后强制终止进程。重启后 pending 工作区自动激活，`activeWorkspaceId` 正确、pending 清空，应用未被注册文件残留阻塞。
2. **已保存笔记后空闲终止**：保存基线笔记并核对 Markdown 字节，强制终止；重启后笔记 ID、标题、正文与文件路径一致。
3. **debounce 窗口内终止**：在编辑器中追加未保存内容，100ms 后终止（小于 500ms 防抖）。重启后内容仍为上一次已保存版本，未出现半写内容。
4. **保存边界竞争（两次）**：分别追加约 200 KB 与 400 KB 内容，在输入后 560ms、620ms 强制终止。重启后两次均恢复到完整的新版本，文件大小与数据库记录一致；断言要求恢复内容必须严格等于旧版本或新版本之一。
5. **最终保存后终止**：确认服务读回最终内容后再次强制终止；重启打开笔记，编辑器恢复完整内容并截屏。
6. **只读核验**：`PRAGMA integrity_check = ok`、`PRAGMA foreign_key_check` 无结果；工作区仅 1 篇笔记、无重复；数据库 `notes.content` 仍为空，正文在 Markdown 文件；文件名/路径与数据库一致；`notes/` 目录没有 `.tmp-` 残留；工作区注册文件中 active 正确、pending 为空。

## 本轮改动

- 笔记正文由直接 `fs.writeFile` 改为通过 `electron/atomicFile.js` 的临时文件替换；临时文件受 `finally` 清理，`EXDEV` 时回退为复制后删除。这样强制终止不会在 Markdown 中留下截断正文。
- 工作区注册与备份状态的原子写在上一轮已使用同一工具，本轮覆盖了“创建后未激活即终止”的重启路径。

## 复现

```bash
corepack pnpm exec cross-env ELECTRON_RUN_AS_NODE=1 electron scripts/m0-inspect-abnormal.cjs .sapere/m0-abnormal/run-m2bl3P/report.json
```

## 边界与未覆盖

- 强制终止使用 Windows `taskkill`，不模拟断电、蓝屏、磁盘写满、文件系统损坏或硬件故障；未在数据库写入过程中注入错误。
- 只覆盖单篇笔记的内容保存与一次标题保存；未覆盖标题/目录移动与保存同时发生、附件、多个工作区切换、资料导入复制中断、媒体下载中断或备份恢复中断。
- debounce 窗口内未保存的输入会丢失；当前没有本地草稿恢复机制。若需要更小丢失窗口，应单独设计并验收草稿持久化。
- 本轮使用开发构建，未对重新打包后的安装版重复全部强制终止场景；打包版已通过正常启动、安装/卸载和工作区持久化检查。
- 未验证自动保存状态提示在强制终止后的 UI 表现，只验证重启后的数据与服务读回。
