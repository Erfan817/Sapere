# M0 本地资料导入验收

日期：2026-11-14。环境：Windows 11 x64；Node 24.16.0；pnpm 10.34.9；Electron 30.5.1（Node 20.16.0、原生 ABI 123）。最终应用构建基于提交 `a3a7b77` 加本轮未提交的导入保护修复。

## 结论

**通过：中文路径独立工作区、本地 UTF-8 TXT 与 Markdown 多文件导入、应用内阅读、完整退出重启后的恢复。删除外部测试源文件后，工作区副本仍可正常读取。**

本轮增加桌面验收脚本和只读检查，并修复本地导入同名覆盖与复制失败无反馈。最终回归同时通过同名文件保护与源文件失效提示，不代表所有格式或异常场景已验收。

## 实际流程与证据

1. 在 `.sapere/m0-import/run-*` 下创建全新的 `user-data`、`中文资料工作区` 和外部测试资料目录，不使用个人工作区。
2. 通过真实界面创建工作区，再完整退出，启动新进程激活；核对 active 工作区与之前 pending 的 ID 一致。
3. 打开“文档 → 上传”，先取消一次原生文件选择，核对提交按钮仍禁用；再选择两份中文文件名资料，点击“上传 2 个文件”。只有操作系统原生选择器由适配器返回测试路径，业务操作均走真实界面与 IPC。
4. 核对资料列表、磁盘 `docs/` 目录、IPC 读取结果与原始 UTF-8 内容一致。分别点击卡片“预览”，核对 TXT 全文、Markdown 标题与代码块、完整文件路径。此处没有调用系统外部编辑器。
5. 确认导入后原始文件未被改变。再通过界面选择内容不同的同名文件，以及一份选择后、点击上传前被移除的测试文件；核对界面分别提示“已保留原文件”和“导入失败”，资料列表仍只有原两份文件，字节及哈希均未改变。关闭应用，再删除最初的两份隔离测试源文件，验证后续读取独立于导入来源。
6. 再启动第三个独立进程，核对工作区 ID 不变、pending 为空、两份资料仍出现在列表中且可预览。工作区文件的 SHA-256 与导入前一致，退出后再次核验。
7. 以 Electron 内置 Node 只读打开 `.reviva/reviva.db`：`PRAGMA integrity_check = ok`；`PRAGMA foreign_key_check` 无结果；工作区注册文件只包含本次工作区，active 正确、pending 为空。

首次成功路径样本：`.sapere/m0-import/run-bjHwKf/report.json`。修复后的最终回归样本：`.sapere/m0-import/run-DbSr7e/report.json`，`success=true`、`errors=[]`、`rendererNetwork=[]`，三个主进程 PID 分别为 40820、18244、40216。已查看 Markdown 阅读、重启后的 TXT 阅读及 `03-import-errors.png` 冲突/错误提示截图；最终只读数据库与文件核验再次通过。

## 实际存储与依赖

- 本地文本资料实际复制到 `<工作区>/docs/<原文件名>`。资料列表扫描文件系统，不以旧 `documents` 表作为索引。新建隔离库中该表记录数为 0，这是当前实现，不能据此判定导入失败。
- TXT 与纯文本 Markdown 的复制、列表和预览路径没有自动调用模型或云解析服务。本轮没有登录账号、配置 API 密钥或发送付费模型请求。
- 桌面页面从初始化监听器建立后到最后关闭，未观察到 HTTP(S) 请求。该监听仅覆盖 renderer 页面请求，不覆盖主进程、子进程及监听建立前的活动，不能推广为整应用完全离线证明。
- Markdown 预览可以加载远程图片；本次资料不含远程图片或其他外部资源。
- PDF 具有本地 Python/PyMuPDF 预检及独立 OCR 配置分支，音视频也有单独服务依赖，未纳入本轮文本验收。

## 复现

先构建当前代码：

```bash
corepack pnpm run build:electron
```

独立运行桌面验收，结束后自动关闭测试 Electron：

```bash
node scripts/m0-document-import.mjs
```

脚本输出 `M0_IMPORT_REPORT` 与本轮报告位置。每次创建全新目录，失败时保留截图和页面文本，并返回非零码。

使用本轮输出的报告路径执行只读核验：

```bash
corepack pnpm exec cross-env ELECTRON_RUN_AS_NODE=1 electron scripts/m0-inspect-import.cjs .sapere/m0-import/run-DbSr7e/report.json
```

应用预览入口 `.claude/launch.json` 中的 `sapere-m0-import` 会运行同一桌面流程，并在 `http://127.0.0.1:1238` 展示报告和真实桌面截图；该入口保留证据服务器供浏览，失败也会展示失败报告。

## 验收边界与待处理项

- 仅覆盖新工作区中两份中文文件名的 UTF-8 本地文本资料，没有验证 PDF、Office、图片、网页、音视频、非 UTF-8 编码、大文件、嵌套目录与多个工作区切换。
- 本次等待复制完成后正常退出；已覆盖同名冲突与选择后来源失效，不覆盖复制中断、强制结束、磁盘写满、权限失败、删除恢复和备份恢复。
- 本轮修复本地上传不检查 `copyFile.success` 和同名静默覆盖：导入传入 `{ overwrite: false }`，主进程使用 `COPYFILE_EXCL` 原子拒绝覆盖并返回错误码；界面分别提示成功、同名跳过和其他失败。只有复制成功的 PDF/媒体才进入解析流程。其他既有 `copyFile` 调用未传选项时仍保持原行为。
- 测试目录、数据库、原始报告与截图均被 Git 忽略，不提交测试资料或个人数据。备份需包含工作区文件及数据库。
- 本轮不涉及 Windows 安装包、受支持 Electron 升级、模型调用与完整学习流程，M0 尚未退出。
