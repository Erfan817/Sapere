# M1 特性规划：轻量创作编辑器（Monaco）

状态：已立项，待 M0 收尾后启动。更新日期：2026-11-14。

## 1. 背景与决策

Sapere 定位为"学习与创作工作台"（commit 9607baa），用户主要是学习者与创作者，不是专业开发者。讨论后确定：

- **不做完整 IDE**（无终端、LSP、调试器、Git 集成），避免与 VS Code 正面竞争和定位漂移。
- **做轻量编辑器**：编辑器 + 本地文件夹挂载 + AI 深度整合，差异化在"AI 助手和文件在同一屋檐下"。
- **内核选 Monaco**（`monaco-editor`）：VS Code 同源内核，Markdown/代码高亮、diff 视图、搜索替换开箱即用；AI 润色可直接用其 diff 视图呈现修改建议。代价是体积较大（约 3MB gzip），可接受，因为它只在编辑器页面按需加载。

## 2. v1 范围（一个里程碑的量）

1. **Monaco 编辑器组件**：封装为 Vue 组件，按需加载（动态 import，避免拖累首屏），覆盖 Markdown、代码与文本文件。
2. **本地文件夹挂载 + 文件树**：通过 Electron IPC + fs 挂载用户选择的文件夹，文件树浏览与打开；与现有工作区（workspace）持久化模型对齐。
3. **AI 润色接入**：现有写作润色 skill 在编辑器内以内联 diff 呈现建议，用户逐块接受/拒绝。
4. **与现有笔记体系衔接**：编辑器作为笔记编辑体验的增强路径，不推翻现有数据模型。

## 3. 明确不做（v1 非目标）

- 终端（xterm.js + node-pty）、LSP/语言服务、调试器、Git 面板。
- 多根工作区、远程文件系统。
- 替代现有 Markdown 预览（`MarkdownView.vue`）——编辑与预览互补。

## 4. 排期约束

- **启动条件**：M0 收尾（验收矩阵"继续推进的顺序"中的密钥加密、Windows 打包、异常退出恢复等项完成）。
- M1 主线是运行时升级（Electron 30 → 受支持版本）与学习闭环设计（见立项书 5.3、7.x）；编辑器为 M1 并行特性，与运行时升级分开变更，不混入同一条分支。
- 体积与启动性能需在验收时核验：编辑器懒加载后首屏耗时不应劣化。

## 5. 验收要点（草案）

- Monaco 组件懒加载成功，首屏 bundle 不含 monaco。
- 中文文件名、长文件、无扩展名文件可打开。
- 文件夹挂载在重启后恢复（复用工作区持久化路径）。
- AI 润色 diff 逐块接受/拒绝后，文件内容与数据库/磁盘一致。
- Electron 主进程 fs 操作全部走 IPC 白名单，渲染进程无直接 fs 权限。
