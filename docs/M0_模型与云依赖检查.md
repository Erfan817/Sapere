# M0 模型与云依赖检查

日期：2026-11-14。环境：Windows 11 x64；Electron 30.5.1；构建自提交 `1498443` 加本轮密钥加固改动。首批验收平台为 Windows。

## 结论

**通过：无 Sapere 账号、外部网络被阻断时，应用可正常启动并进入本地路径；模型服务商可配置并保存到本地，连接失败有明确提示；本次流程未发出任何外部 HTTP(S) 请求。**

本轮确认了以下事实：

- Sapere 没有官方账号、充值、订阅或官方云模型；不需要登录即可创建和使用本地工作区、笔记、资料与设置。
- 模型由用户自带：内置多家第三方 OpenAI/Anthropic 兼容预设，以及本地 Ollama / 自建兼容服务入口。
- 云端生成不是核心学习路径的强制门禁。PPT、研究报告、学习指南支持本地与云端模式；播客目前仅云端。云端模式要求登录令牌与云服务地址，未登录时会明确拒绝，不会静默改走其他收费服务。
- 自动更新处于关闭状态，检查更新只显示本地开发版说明，不请求上游更新源。
- 服务商 API Key 已改为通过 `safeStorage` 加密后存入工作区 SQLite 的服务商表；旧的兼容设置行不再保存密钥副本。
- 设置导出默认脱敏：不包含服务商 Key、网页导入 Key、代理密码、网关 Key 和 B 站 Cookie；重新导入同一份脱敏文件会保留本机已有密钥。

本轮**没有**发送真实模型请求，没有登录任何云服务，没有产生 API 费用。

## 实测流程与证据

证据：`.sapere/m0-model-cloud/run-D7DRRC/report.json`，`success=true`，页面错误为空，外部请求为零。先前样本 `run-Cpcgv0` 保留了加密前的检查结果。

1. 在 `.sapere/m0-model-cloud/run-*` 下创建全新的 `user-data` 与中文工作区，不使用个人数据。
2. 首次启动创建工作区；不登录、不配置模型即可完成目录授权。
3. 第二次启动后，将 Chromium 网络层指向本机黑洞代理，并在主进程替换全局 `fetch`：外部地址一律记录并拒绝，回环地址保持可用。先发出一次受控外部请求，确认两套检测器都能记录，再清空记录。
4. 进入“设置 → 模型服务”，选择内置 Ollama 预设，填写占位 API Key 与 `http://127.0.0.1:9/v1`，等待自动保存；通过应用设置接口读回配置一致。
5. 通过应用设置接口导出全部设置：导出内容不含占位 Key，服务商标记为已脱敏；将同一份导出重新导入，本机保存的占位 Key 与 Base URL 保持不变。
6. 启用模型并点击“测试连接”，请求指向关闭的本机端口；界面在 22ms 内显示“连接失败 / fetch failed”，应用无崩溃、无页面错误。
7. 依次打开账号、新手教程、网关服务与系统版本页面：账号页说明不需要 Sapere 账号；网关服务默认监听本机；检查更新只提示“尚未启用安装包自动更新”。
8. 结束前读取两套检测记录：Chromium 外部请求、主进程被拦截的外部 `fetch`、黑洞代理连接均为空，页面错误为空。
9. 关闭应用后以只读方式打开工作区数据库：`PRAGMA integrity_check = ok`、`PRAGMA foreign_key_check` 无结果；服务商表中的占位 Key 以 `safe:` 前缀加密保存，兼容设置行中不再出现明文 Key。测试使用的是占位值，不是真实密钥。

## 依赖矩阵

“本地”指不依赖 Sapere 账号或 App 自带云服务；用户自带的模型与第三方服务仍按其自身网络与计费规则运行。

| 能力 | 当前依赖 | 无账号/断网时的表现 |
| --- | --- | --- |
| 工作区、笔记、资料导入与预览、回收站 | 本地文件与 SQLite | 可用；Markdown 中的远程图片仍会请求外网 |
| 设置、主题、快捷键、本地网关配置 | 本地 | 可用；网关默认仅监听 `127.0.0.1:1210`，可选局域网 |
| 对话、Agent、技能与多数生成（导图、图表、闪卡、测验等） | 用户配置的模型服务 | 未配置模型时入口提示配置；可用本地 Ollama 或自建兼容服务 |
| PPT、研究报告、学习指南 | 本地内置 Agent 或云端业务服务 | 本地模式使用用户模型；云端模式需要登录令牌与云服务地址 |
| 播客生成 | 云端业务服务 | 仅云端；未登录时明确提示先登录 |
| PDF 解析 | 本地 PyMuPDF 预检；可选 OCR 服务 | 缺少本地解析依赖时失败并提示；OCR 需要另行配置 |
| 网页导入、联网搜索、深度研究 | 外网与检索服务（Tavily、SearXNG、Bing、Exa、Jina、Firecrawl 等） | 无网络时任务失败并提示；不自动切换其他付费服务 |
| 音视频解析与语音转写 | B 站等外部来源、本地 Whisper 兼容服务或第三方 ASR | 需要网络或用户自备服务；未配置时提示依赖 |
| 账号登录 | 可选，后端为 `VITE_CLOUD_BASE_URL` 或本机 `localhost:8000`，不是 Sapere 自营服务 | 不需要登录即可进入本地核心路径 |
| 自动更新 | 已关闭 | 只显示开发版说明，不访问更新源 |

## 密钥加密与导出脱敏

- LLM、图像、语音服务商的 Key 写入前经 Electron `safeStorage` 加密，数据库列以 `safe:` 前缀保存；读取时解密后交给业务代码。旧数据库中的明文 Key 在启动时迁移为密文，不改变服务商配置。
- 兼容设置行（`providers`、`imageModels`、`mediaSpeechSettings`）不再保存 Key 副本；旧数据会先迁入服务商表再清理，避免为了加密而丢失配置。
- 网页导入 Key、代理密码、B 站 Cookie 以加密 JSON 保存；本地网关 Key 仍使用哈希校验，原始值同样经 `safeStorage` 加密。
- 设置导出不包含任何密钥：服务商与网页导入配置保留结构并标记 `apiKeyRedacted`，代理密码、网关 Key、B 站 Cookie 直接排除。导入脱敏文件时按服务商 ID 合并，保留本机已有 Key；导入旧版含密钥文件仍可恢复其中的 Key。
- `safeStorage` 不可用时（例如缺少系统密钥环）不会假装加密，Key 保持明文并在验收记录中说明；这是环境限制，不是静默降级。
- 数据库备份恢复到不同机器或不同操作系统用户时，`safeStorage` 无法解密原 Key，服务商会显示为未配置，需要重新填写。这是加密的预期代价，备份恢复流程需要明确提示。
- 登录令牌由渲染进程持久化保存在本机应用数据中；本轮未登录，未产生令牌。

## 检测方法与边界

- Chromium 网络层：主进程安装 `session.defaultSession.webRequest` 监听全部 HTTP(S) 请求，并配置本机黑洞代理记录任何外连尝试。
- 主进程 Node 请求：启动后替换全局 `fetch`，外部地址记录并拒绝，回环地址放行。
- 两套检测器都用一次受控外部请求验证过，避免“检测器失效却被当作零请求”。
- 检测器在应用启动完成后安装，启动早期的 Node 层请求不在覆盖范围内；Chromium 与代理可从进程启动即记录。操作系统级、DNS 层或其他子进程（如 Python 工具、命令行工具）的网络活动不在本轮范围内。
- 本轮未调用真实模型、OCR、语音或云端生成，因此只证明“未配置/断网时不越权外连与明确失败”，不证明各服务商的真实可用性、流式输出、工具调用或计费行为。
- 仅验证 Windows 本机开发构建，不代表安装包、代理/VPN、企业网络或 macOS/Linux 行为。

## 复现

先构建当前代码：

```bash
corepack pnpm run build:electron
```

运行隔离桌面检查（会创建临时工作区、使用占位密钥与本机黑洞代理，不发起真实外部请求）：

```bash
node scripts/m0-model-cloud-check.mjs
```

脚本输出 `M0_MODEL_CLOUD_REPORT` 给出报告路径。随后用 Electron 内置 Node 只读核验配置与数据库：

```bash
corepack pnpm exec cross-env ELECTRON_RUN_AS_NODE=1 electron scripts/m0-inspect-model-cloud.cjs .sapere/m0-model-cloud/run-D7DRRC/report.json
```

`.claude/launch.json` 的 `sapere-m0-model` 入口会运行同一流程，并在 `http://127.0.0.1:1239` 展示报告与截图。
