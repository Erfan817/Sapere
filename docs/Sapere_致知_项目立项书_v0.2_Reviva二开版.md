## 1. 立项摘要

**Sapere 致知是一款以 Reviva 为底座二次开发的 AI 桌面学习工作空间。** 它提供精选学习内容，也允许用户导入自己的资料，围绕“理解 → 练习 → 反馈 → 复习 → 继续学习”组织持续学习。

项目直接继承 Reviva 的桌面框架、工作区、资料与笔记、Agent/Skills 和内容生成能力，重点补充课程组织、持久学习记录和间隔复习。第一套内容以 LLM / Agent 入门与实践为样板，验证平台对其他主题的可扩展性。

**本次立项的核心决定：**

1. 以 Reviva 为唯一应用底座，不从零重建桌面应用，不同时维护第二套 OpenTutor 应用。
2. 桌面优先；首批验收平台为 Windows 11 x64，macOS / Linux 在取得实际测试条件后分阶段纳入支持。
3. 沿用 Electron + Vue + Vite + SQLite 和上游 Agent 运行体系；新增核心业务优先使用 TypeScript，不整体改写已有 JavaScript。
4. 首版围绕一个真实学习流程交付，不以扩充 Agent 数量、生成工具数量或模型数量作为成功标准。
5. 学习事件与评分保存是复习、分析的基础，先做数据闭环，再做算法和统计展示。
6. 使用成熟的间隔复习库作为优先方案；OpenTutor 作为学习机制参考和按需移植来源，不直接承诺继承其全部算法。
7. 数据迁移、备份恢复、受支持的 Electron 运行时、模型成本控制和基础测试进入首版质量要求。
8. 保留上游与内容来源信息。个人自用开发继续推进；公开发布代码或安装包前，按实际授权和资源许可另做分发检查。

## 3. 产品定位与目标用户

### 3.1 定位

> **围绕你的资料，帮助你理解、实践，并记住所学的 AI 桌面学习工作空间。**

英文名 Sapere；中文品牌致知；“知也”作为可选简称；品牌精神沿用 *Sapere aude — 敢于求知*。域名、商标和包名尚未完成权利检索，个人开发阶段不作为阻断项，公开发布前检查。

“本地优先”指资料、笔记、学习事实和复习队列优先保存在本机；选择云模型、转录或其他联网工具时，相应内容仍可能发送到外部。它不等于全部功能离线，不等于自动具备跨设备同步。

### 3.2 首批用户与场景

首批用户是项目发起人本人，以及未来自愿试用的少量中文技术自学者。核心场景是利用精选教程、文章和项目资料，学习 LLM 应用开发与 Agent 基础。

| 场景 | 用户目标 | 产品承接 |
|---|---|---|
| 初次进入 | 不知道先学什么 | 选择学习包，查看先修要求与明确成果 |
| 理解章节 | 看不懂某个概念 | 结合原文讲解、举例、来源定位 |
| 检查理解 | 不确定是否真正理解 | 无提示作答、练习反馈、参考答案与解释 |
| 动手实践 | 把知识用到一个小项目 | 实践任务、验收清单、记录完成证据 |
| 过几天回来 | 忘记上次进度 | 今日待复习、继续上次章节、薄弱项 |
| 加入个人资料 | 学习包不能覆盖所有问题 | 使用已有工作区导入资料和笔记，挂接学习单元 |

课程可以注明“需要基本 Python 知识”，提供补充阅读，不要求首版覆盖完全零编程基础到高级工程师的全部路径。

### 3.3 MVP 完成定义

在 Windows 11 x64 上安装并启动 Sapere 后，用户无需安装 Node/Python 开发环境即可完成基础学习：

**选择学习包 → 阅读一节 → 基于资料提问 → 提交练习 → 保存记录 → 进入复习 → 重启后继续 → 导出/备份并恢复。**

首次模型配置可需要用户自己的服务凭据；未配置模型时，阅读、人工审阅过的固定练习、历史记录和复习队列仍可使用。API 不可用不能让整个工作空间失效。

### 4.3 非目标与范围控制

首版不建设 SaaS、支付订阅、多人协作、统一云平台或自动代码评测沙箱；不重写已有编辑器、知识库和通用 Agent 框架；不以更换 UI 框架或全面 JS→TS 迁移作为里程碑。

不在 MVP 强行加入 LOOM/LECTOR/BKT 全家桶。先证明现有学习记录与简单复习可靠，再评估更复杂的自适应机制。

不自动执行课程下载包里的脚本、不自动运行模型生成的代码。实践任务首版以说明、检查清单和用户主动提交证据完成；自动化代码实验环境单独立项评估。

范围新增应写明用户问题、验收方法、依赖、预计成本及替换/延期哪项工作。阻塞数据正确性的问题优先于外观和新增工具。

## 5. 底座与技术方案

### 5.1 选用 Reviva 的理由

Reviva 提供了符合目标的桌面窗口、Vue 工作台、本地工作区、SQLite、Agent/Skills、资料与产物生成，以及迁移、备份和更新入口。二开可以把主要精力放到学习业务。

这是一项产品与工程复用决策，不代表已确认上游所有功能成熟。个人自学开发按当前用途推进；授权状态和公开分发处理见第 11 节。

OpenTutor 保留为参照：其 MIT 许可可核，学习算法存在真实调用，但源码核验发现前端复习请求缺少后端保存所需标识。不能将其全部学习内核未经测试直接移入。

### 5.2 技术选型表

| 领域 | 当前选型 | 使用边界与决策 |
|---|---|---|
| 桌面运行 | Electron | 继承窗口与 IPC；从上游 Electron `^30.0.1` 迁至实施时受支持主版本，目标版本由兼容 spike 决定 |
| UI | Vue 3 + Vite，沿用 Naive UI / UnoCSS / Pinia / Vue Router | 沿用现有体系，不再引入 React/Next 作为第二套 UI |
| 语言 | 保留 JS，新增关键服务与契约优先 TS | 先验证 Electron/Vite构建兼容；上游 JS 可通过适配器消费，不全仓重构 |
| 应用服务 | Electron 本地服务的模块化扩展 | 沿用 Agent、生成任务、数据库、工作区；CPU密集任务放 worker/utility process，避免阻塞主进程 |
| AI 编排 | 沿用 LangChain / LangGraph / DeepAgents 和 provider profiles | 不更换现有运行器；补能力检测、版本记录、调用限制、取消和错误分类 |
| 数据 | SQLite + better-sqlite3 + 工作区文件 | 优先同一工作区数据库的独立表和 repository，不引入 PostgreSQL/Redis/独立向量服务作为首版必需 |
| 课程格式 | Markdown + JSON manifest + 资源文件 | 版本化、可追溯、可离线阅读；不直接支持任意可执行插件包 |
| 数据校验 | 复用 Zod | 对课程清单、IPC输入、生成题目、评分结果做结构校验；校验通过不等于内容正确 |
| 复习算法 | 优先评估 `ts-fsrs` | 只负责确定性排程；锁定版本与参数，契约测试通过后采用，不手写 FSRS 公式 |
| 测试 | 复用 Node test；新增 Vue组件测试与桌面冒烟 | Vitest / Vue Test Utils 为候选；Playwright Electron适配为实验支持，需可行性验证，必要时用 WebdriverIO |
| 包管理/构建 | pnpm lock + Vite + electron-builder | M0固定 Node与pnpm版本、锁文件和原生依赖构建条件；保留镜像可配置但不以镜像替代完整性校验 |
| 发布/更新 | Windows NSIS优先，沿用 updater结构 | 独立 appId、产品名、数据路径与更新源；未建立Sapere发布渠道前关闭自动检查上游安装更新 |

Node 版本以 M0 上游依赖与目标 Electron 兼容验证为准，并写入工具链文件；本立项书不猜测一组未经构建验证的版本组合。Electron 所带 Node 与构建机 Node 必须区分。

### 5.3 Electron 升级是基础工作

官方文档采用最近三个稳定主版本支持策略；官方发布表显示 Electron 30 于 2024-10-14 结束支持。上游声明 `^30.0.1` 不能作为 Sapere 长期运行时目标。[E1][E2]

M0 先重现上游基线；M1 再单独升级并测试，避免将运行时升级、全面重构、课程功能同时混入一个变更。重点核验 better-sqlite3 原生 ABI、preload CommonJS、Vite Electron插件、文档/HTML渲染、打包资源和 updater。升级无法直接完成时记录阻塞，旧基线仅用于隔离开发测试，不作为“安全稳定版”发布。

### 5.4 模块边界与上游改动控制

建议新增以下职责，具体目录由 ADR 确认，不假装上游已经存在：

| 新职责 | 主要任务 | 与上游连接 |
|---|---|---|
| CoursePackageService | 验证、安装、更新课程包与引用资源 | 工作区、文件服务、资料导入 |
| LearningSessionService | 章节进度、会话、作答与练习提交 | 课程视图、现有测验/闪卡预览 |
| ReviewService | 状态机、调度库、到期队列、复习日志 | SQLite、今日学习入口 |
| LearningRecordRepository | 学习事实与幂等事务 | 同一工作区数据库，独立 Sapere表 |
| LearningSummaryService | 从真实记录计算基础复盘 | 只读查询；不把模型猜测写成事实 |
| UpstreamAdapters | 映射上游资料、生成产物和画像事件 | 避免把业务规则散落在main.js和预览组件 |

架构关系：Vue 页面调用窄化 preload 方法；主进程服务校验后访问 repository；模型输出经校验和用户交互转成业务命令；调度和数据写入由确定性代码完成。

课程视图和状态通过专用 IPC契约接入。Renderer不直接打开SQLite，LLM不直接拼接执行SQL、不直接改复习时间。尽量复用现有预览组件，评分提交时增加明确业务接口；上游扩展点不足的地方做小而可记录的改动。

## 6. 课程与内容建设

### 6.1 首套学习包

工作名称：**《从 LLM 到第一个 Agent》**。目标是在已有基本编程知识的前提下，理解关键概念，完成一个可解释、可调试的小应用。预计学习时长在试学后给出，不使用“几小时精通”承诺。

| 单元 | 学习目标 | 实践/检查证据 |
|---|---|---|
| 1. LLM 能力与边界 | 理解 token、上下文、幻觉、成本和隐私 | 用例判断题；解释一次失败 |
| 2. 调用模型与结构化输出 | 理解输入输出、流式、schema与错误处理 | 在自行配置的环境完成最小调用，或分析离线示例 |
| 3. 资料问答与 RAG | 区分检索、生成、引用和内容覆盖 | 导入自己的资料，检查答案是否得到原文支持 |
| 4. Agent 与工具 | 区分模型建议、工具执行、状态与停止条件 | 分析/实现一个有限工具循环，保留运行记录 |
| 5. 调试与评估 | 用失败样例检查修改结果 | 定义几个可检查任务，比较修改前后表现 |
| 6. 综合小项目 | 组合资料、工具与约束完成目标 | 使用明确验收清单完成个人助手项目复盘 |

内容按供应商通用概念组织，实际 API 示例可分 provider 分支。示例注明依赖、验证日期和费用前提；不在应用安装包中内置 API key，也不默认要求付费模型。

### 6.2 课程包结构与生命周期

建议结构：`manifest.json`、`units/*.md`、`exercises/*.json`、`assets/`、`SOURCES.md`、`LICENSES/`、`CHANGELOG.md`。这属于待实现协议，不是现有目录。

清单至少包含：稳定package_id、版本、标题、语言、先修、学习目标、章节与概念ID、内容来源URL/仓库提交、文本/代码/图片各自许可、再分发模式、所需应用协议版本、文件清单与校验值。下载有可信来源记录；校验值验证完整性，不等于证明作者可信。

生命周期：发现 → 核对来源与许可 → 整理/适配 → 人工审阅 → 试学 → 安装 → 更新 → 归档。首批正文、参考答案、评分依据和概念映射人工复核；AI辅助生成部分显式标记。

更新规则：

- 同版本重复导入幂等；新版本先检查应用兼容性和来源，再安装。
- 用户进度绑定已学习课程版本和稳定章节ID；用户笔记保存在独立可写层，不覆盖作者原始正文。
- 题目或评分规则发生实质变化时创建新修订；旧答案仍指向旧题目快照。
- 不能自动映射的章节或卡片变更提示用户选择，不悄悄清空学习进度或复用旧掌握状态。
- 一键下载失败不破坏已安装课程；正文链接模式与随包离线正文模式明确区分。
- 包解压验证相对路径、目标目录、总大小与文件数；拒绝越界路径、符号链接逃逸及脚本安装钩子。

### 6.3 候选内容来源

优先考察 Datawhale Hello Agents、Microsoft AI Agents for Beginners、Hugging Face Agents Course；以官方正文/许可证和来源快照决定实际内置范围，不用仓库star排序代替教学选材。

优先选择一套中文主线，其他课程仅补充，避免把三套相似教程全部塞入首页。官方文档用于校准 API 和工具概念；示例能下载不等于正文、图像和译文都具有相同的再分发许可。

具体补充核验记录见第17节。未确认再分发权限的材料，使用链接和自编导读；不随安装包复制全文。

## 7. 学习数据与复习机制

### 7.1 事实、推断与展示分开

- **学习事实**：作答、评分、是否提示、用户确认、实践证据、复习评分和时间。
- **派生结果**：章节完成度、到期时间、历史正确率、提示使用率等可重新计算数据。
- **模型推断**：解释质量、可能误区、学习建议与估计置信度。

上游学习画像可继续使用，但其中 `source_kind=model_inferred` 的事件不能自动当作考试结果或卡片完成。Sapere的业务表对真实作答负责，画像通过带来源的适配事件更新；不复用上游“看起来相似”的表来混存不同语义。

### 7.2 建议最小数据模型

下表为逻辑模型，不直接等同最终SQL；M1设计评审时确定表结构、索引与保留策略。

| 实体 | 关键字段/关系 | 关键约束 |
|---|---|---|
| CoursePackageVersion | package_id/version/hash/license manifest | 包版本唯一，安装状态可恢复 |
| Enrollment / UnitProgress | 课程实例、版本、章节、状态、位置 | 内容与个人进度分离，支持重开 |
| ExerciseRevision | 稳定题目ID、修订、内容快照/哈希、参考答案、评分规则、来源 | 旧作答能还原当时题目，不被新版本覆盖 |
| Attempt | attempt_id、request_id、题目修订、答案、首次/重试、提示、时间、评分类型、分值 | request_id幂等；保留原答案与评分来源，人工更正留版本 |
| ReviewCard | card_id、题目/内容修订、启用状态 | 卡片ID不能靠front文本截取生成 |
| ReviewState | 卡片、调度库版本/参数、算法状态、due_at、revision | 数据库为准，不靠组件ref/localStorage维持 |
| ReviewLog | review_id、rating、前后状态、发生时间、操作来源 | 与状态变更同一事务；重复提交不重复排程 |
| PracticeEvidence | 单元/任务、用户提交结果、路径/备注、核对方式 | 不默认上传项目文件或自动执行代码 |
| LearningEvent | 事件ID、实体引用、类型、时间、来源 | 精简本地事实流水，区别于诊断日志；可导出/删除 |

时间使用 UTC存储，按本地时区展示；跨时区、夏令时、系统时钟变化不改写历史。涉及排程的服务使用可替换时钟，以便测试。

### 7.3 复习策略

优先用 `ts-fsrs` 等成熟TS库，M1完成许可证、依赖与接口验证；若未通过，写ADR选择替代库，不临时自创公式。采用固定已验证参数，首版不根据极少个人样本声称训练出个性化最优参数。

每次复习：读取卡片与状态 → 用户回忆并评分 → 服务验证request_id、rating与状态revision → 调度库计算 → 事务写入ReviewLog/ReviewState/必要事件 → 成功后UI推进。失败时留在当前题，明确显示未保存，允许幂等重试。

客观题正确率与FSRS的Again/Hard/Good/Easy不是同一信号。首版以明确说明的用户回忆评分作为排程输入，不把“答对”静默等同Easy；考试/练习记录先独立保存。

今日学习优先展示到期复习与上次未完成单元。用户可暂停、归档、重学；不得因为错过几天而制造不可解释的巨大任务压力。卡片暂停、删除、课程归档的语义应单独定义。

### 7.4 学习复盘与证据

首版展示可追溯统计：已完成章节、首次无提示正确率及样本数、重试变化、提示使用情况、到期/完成复习、延迟回忆任务结果。没有记录时显示暂无数据，不伪造曲线，不把统计汇总命名为“科学掌握度”。

重复同一道题的涨分不能单独证明迁移能力；用户自评不能替代客观测试。7日/14日后采用未看答案的回忆任务或经审阅的等价题，注明样本、时间、提示和评分规则。单人试用只支持个人观察，不作因果推断或“提升X%”产品成效宣称。受控A/B、长期参数训练后置。

### 7.5 资料、讨论与复习素材的连接

吸收旧规划“讨论沉淀为复习素材”的想法，建立课程、问答、媒体笔记、个人错题与复习卡之间的来源关联。既有Reviva笔记/Wiki/生成产物优先复用，不另做一套产物系统。

转换流程：用户选择一段内容或结束讨论 → 生成要点、可能误解和建议卡片草稿 → 校验结构与引用 → 展示原文、答案与来源 → 用户编辑/确认 → 创建独立卡片并加入同一ReviewService队列。

生成服务不直接更新ReviewState。卡片保留来源资料ID、章节/页码/时间戳或消息ID、内容修订与生成版本；资料删除或引用失效时提示，不悄悄改写已学内容。重复确认通过请求ID防止重复建卡；一次不适合形成卡片的讨论可以不产卡，不把“至少生成一张”作为学习质量指标。

首次MVP可复用“选择生成卡片→确认保存”入口；讨论专用汇总在学习小组试点再扩展。用户确认卡片正确不等于用户已经记住该知识，之后的回忆评分独立记录。

### 7.6 可选学习小组：MVP后的教学交互试点

**理论依据与对照实现：**本节设计对应 ICAP 学习框架（Chi & Wylie, 2014）的 Interactive 层级——学习者与对话方围绕内容来回推理、互相回应并修改，投入深度高于被动阅读和单向问答。已有公开对照实现 [obsidian-icap-agent](https://github.com/EdwinZhanCN/obsidian-icap-agent)（MIT，2026-11-14 核对 README 与 DESIGN.md）验证了单 agent 追问模式可跑通；该实现将"可见的多 agent 编排"明确列为非目标，Interactive 仅由单个 agent 的针对性追问实现，并采用"无聊天面板、反馈嵌入原笔记"的形态。本试点保留双角色（助教+同伴）设计以覆盖"辨析含错解答"场景，但承认单 agent 追问是更保守的对照方案：若 7.6 验收发现双角色编排收益不足，可收缩为该对照模式，不视为失败。

**产品位置：**与默认一对一学习并列的可选模式，不是产品主形态；默认关闭，用户主动进入，随时结束、暂停或回到单聊。不要求每个章节都开小组，不影响未启用时的正常学习。

**最小试点：**仅文本，1名AI助教、1名AI同伴和用户，围绕首套LLM/Agent课程的一个已审阅易错概念。AI角色是交互分工，不强制每个角色独立进程、独立模型或并行运行。优先验证串行受控流程，不引入新的多Agent框架。

| 角色 | 作用 | 约束 |
|---|---|---|
| 助教 | 设定问题、邀请用户解释、核对并总结 | 有参考答案/来源；不给未经核实的结论背书，不无限追问 |
| AI同伴 | 提供待辨析的解答或追问 | 明确标为AI模拟；可能包含错误，不能伪装成真实同学的学习经历 |
| 用户 | 判断、解释、提出疑问与总结 | 保留发言机会；可请求提示/答案、跳过或退出，不以强迫发言代替学习 |

试点流程：选择概念/错题 → 展示讨论目标及AI模拟说明 → 助教提出一道问题 → 同伴给出待辨析解答 → 等待用户回应 → 助教依据参考资料反馈 → 用户选择补充/查看答案/结束 → 生成带来源的总结与卡片草稿 → 确认后入公共复习队列。

用户不回应时暂停，不自动让AI无限续聊。典型误解优先来自审阅过的题库或用户已确认的错题，不让模型随意编造事实性错误当成标准教学内容；纠错结束显式给出正确解释，未能核实的部分标记不确定，不进入正式卡片答案。涉及故意设置误解时，题面提示“下面是待辨析答案，可能有错”。

**Reviva扩展方案（待技术spike，不冒充已实现）：**复用现有AgentService、DeepAgents/LangGraph运行体系、对话UI和生成模块；以独立GroupLearningSessionService或等价适配层管理会话状态，使用Electron IPC/既有流式事件，不照搬OpenTutor的Python orchestrator、SSE或Block目录。M1只保留兼容字段/接口空间，不提前实现整个模式；进入P2后再做ADR和任务拆分。

建议会话状态：准备、AI发言、等待用户、反馈、暂停、结束、失败/取消；保存session_id、turn_id、speaker_id、mode、user_response_id、引用、模型/提示词版本和预算。等待用户、关闭窗口或取消后可恢复已提交轮次，不在重启时自动续费跑完讨论；重试、模式切换、退出不重复记账或重复建卡。会话共享受控摘要，避免同伴意外提前获得本应由用户回忆的参考答案。

**学习证据与成本：**记录用户是否回应、是否用提示、给出的解释、评分依据及是否人工确认。参与次数、讨论时长、纠正AI的次数是过程指标，不能直接增加掌握度或替代延迟回忆测试；基于标准答案得到的纠错得分标记为受提示场景，不能冒充首次无提示成绩。模型评分仍属推断，不能自己证明教学有效。

调用次数、轮数、每轮字数、总时长和token预算在启动时有上限，取消可中断；不默认启用无限子Agent。是否为同伴选更便宜模型取决于实际评测与用户配置，不在立项中预设小模型一定足够。

**进入条件与独立验收：**M3的作答保存、卡片确认入队、调度和取消机制已通过，再用少量审阅题开展试点。验收覆盖默认单聊不变、角色身份清楚、等待用户不推进、请求答案/跳过/退出可用、中断恢复、预算耗尽、错误答案得到纠正、无有效总结不落卡、重复确认不重复建卡和回到单聊。试点不通过则保持关闭；语音小组、多个同伴辩论与真人多人协作仍后置。P2工作需单独估算，不加入MVP的34–52人日承诺范围。

## 8. AI 能力、成本与失败处理

### 8.1 模型接入与能力契约

保留上游provider机制；按模型验证流式、工具调用、结构化输出和上下文限制，不能假定所有OpenAI-compatible端点能力一致。支持至少一个已验证本地配置和一个用户自带云配置；不保证任意模型都有相同教学质量。

模型适配应记录provider、model、提示词/评分规则版本与运行ID。首版不新增第二套SDK编排框架；仅当现有适配层不支持必要能力时局部补充。

### 8.2 输出质量与运行控制

- 课程生成、题目生成、反馈与模型推断必须经schema验证；缺字段、非法题型、超长输出和截断有明确失败状态。
- 客观题用确定性规则判分；AI主观反馈标为建议，保存依据，允许人工更正。
- 内容不受资料支持时明确表示无法确认，能定位章节/来源，不把相关性当作引用正确性。
- 保留重试、取消、超时和中断恢复；网络重试与业务提交幂等，避免重复扣费和重复写入。
- 每次任务限制模型/工具调用次数、总耗时与可选token预算；上游部分默认0表示不限，Sapere学习任务不直接继承无限预算。
- 费用有来源才显示实测/估算，不能把token估算写成真实账单；普通CI用mock，不自动消耗模型费用。

### 8.3 能力降级

| 条件 | 可继续 | 受影响与提示 |
|---|---|---|
| 未配置模型 | 阅读、固定题、笔记、记录、调度 | 讲解/生成入口提示配置，不阻塞应用 |
| 云端断网或额度不足 | 本地资料与学习记录 | 当前任务可重试/取消；不悄悄切换其他收费服务 |
| 未安装本地模型/转录组件 | 基础课程学习 | 相关任务说明依赖，不自动下载大模型 |
| 未连接上游账号/商业后台 | 必须能进入个人核心学习路径 | 账户、积分等不属于Sapere自学流程的入口隔离；是否存在强制门禁由M0实测确认 |

## 9. 数据、安全与桌面可靠性

这些要求直接服务于“学习资料和记录不能丢、模型不能越权”，不是额外建设企业安全平台。

### 9.1 本地数据与迁移

- Sapere使用独立appId、用户数据/工作区与数据库，默认不打开原Reviva数据库；不通过全仓字符串替换直接改`.reviva`路径。
- 需要导入Reviva数据时，先做只读检查和备份，提供显式导入流程；原数据库不作为试验对象。
- 同一工作区优先复用SQLite连接与事务；新增`sapere_`业务表与独立迁移台账，避免与上游版本号碰撞。跨表备份保持一致。
- 已发布迁移不可重写；迁移前备份，失败回滚事务并停止写入，不半成功继续启动。
- 已发现上游v10删除重建学习表，导入旧数据库前必须识别适用版本并验证，不假定历史学习记录无价值。
- 定义应用版本、数据库版本、导出协议和课程协议兼容性。旧应用遇较新schema拒绝写入，避免降级破坏数据。
- 崩溃恢复与数据库完整性检查有可操作提示，不能用“自动重建空库”掩盖损坏。

### 9.2 备份、导出与恢复

沿用上游备份能力，核验其SQLite快照、工作区文件、资源、学习表和manifest覆盖范围。活跃数据库通过SQLite受支持的备份方法产生一致快照，不能仅把WAL模式主文件复制当作完整备份。[E5]

区分完整应用备份与用户可读导出：前者为恢复；后者提供课程清单、笔记、作答/复习记录JSON或CSV和来源信息。导出默认排除API密钥；完整备份若含密钥，必须显式提示并提供可保护方案。

测试必须真实恢复到新的临时工作区，核对记录数量与关键内容；“生成ZIP成功”不等于恢复验收。发生升级故障时保留原备份，不能拿已迁移的新库直接交给旧应用。

### 9.3 Electron边界

依据官方建议保持contextIsolation、关闭nodeIntegration，验证sandbox、CSP、IPC发送者与输入、工作区路径权限、导航和外部链接allowlist。[E3]

导入文档、网页、课程和模型生成HTML均视为不可信内容。产物预览不向其暴露应用级preload/文件工具；需要脚本的交互产物在隔离环境按最小权限运行。学习包不能通过提示词或manifest自行获得Shell、MCP或全盘访问权限。

模型与工具输出不具有用户授权效力。文件写入、删除和代码执行沿用明确能力边界；核心学习包默认为阅读与作答所需权限，不主动启用全量工具。

### 9.4 密钥与隐私

核验现有API key读写和日志路径；数据库有api_key字段并不证明明文或加密，必须追踪实现后判断。目标是主进程使用OS保护的secret存储，界面只显示掩码，导出和诊断日志脱敏。

可评估Electron safeStorage；根据最终选定运行时使用可用API，验证操作系统后端。Linux不安全降级时不悄悄持久保存密钥，SQLite不会因使用safeStorage自动整体加密。[E4]

学习事件默认仅本地保存；默认不上传对话、课程记录或诊断信息。模型和ASR外发内容、服务提供方、是否计费在配置与任务入口可见；项目不作“绝不联网”承诺。

### 12.2 MVP验收用例

1. **AC-01 安装启动：**在记录配置的Windows11 x64干净环境安装并打开，无需另装开发工具；正确显示缺失可选能力。
2. **AC-02 无模型阅读：**不配置模型，仍能学习固定内容、完成客观题、查历史与复习；不会被上游登录/积分入口卡住。
3. **AC-03 课程完整性：**非法清单或越界资源被拒绝且不污染工作区；重复安装幂等。
4. **AC-04 引用与问答：**对固定样本文档提问，能返回可定位出处；无答案的样例不能以无依据回答通过验收。
5. **AC-05 提交持久化：**首次/重试/使用提示均被记录；强制关闭后重开仍能还原；重复request_id不会重复计分。
6. **AC-06 复习一致性：**fake clock推进日期后到期队列正确；评分后状态与日志同事务；数据库失败时不推进UI；重启结果一致。
7. **AC-07 内容升级：**新版本不覆盖个人笔记、不重写旧题答案；无法自动映射进度时有可理解处理。
8. **AC-08 模型失败：**无效密钥、超时、额度不足、截断和取消均有可恢复状态；不产生伪成功或重复业务记录。
9. **AC-09 备份恢复：**包含资料和学习记录的备份能恢复到新工作区；导出不意外暴露密钥；损坏备份不覆盖原数据。
10. **AC-10 升级/回退：**覆盖至少一个真实旧版快照升级；失败可从备份恢复；旧应用不会写入不兼容新库。
11. **AC-11 权限：**课程/产物无法访问授权根外文件或调用原始IPC；HTML预览和链接遵守隔离策略。
12. **AC-12 个人试学：**本人连续试学至少14天，完成实际章节、跨日复习和一次备份恢复，记录问题与修复；不据单人样本宣称普遍学习效果。

### 12.3 体验与性能预算

以下为待M0实测校准的工程目标，不是已达成指标：参考环境Windows11 x64、16GB RAM、SSD，不运行本地模型时冷启动主界面目标≤5秒；本地翻卡/导航可见反馈目标≤200ms；10000条个人学习记录的常见查询目标≤300ms。每项记录测量条件、样本和口径。

模型延迟单独统计，不包含在本地界面承诺内。大文件解析、打包备份和转录显示进度并可取消，不阻塞窗口。最低配置、安装体积和内存预算由基线测量确定，不沿用未经核实的宣传数字。

支持键盘完成核心练习、清晰焦点、字号缩放、中文长文本和错误状态。首版不为做看板而引入复杂图表依赖，简单文字/表格足够表达学习事实。

### 12.4 中文检索、多模态与首学体验的专项验证

**中文检索：**在改分词、embedding或混合检索之前建立一组可人工核对的小样本：中文概念/同义问法、中英混合术语、代码标识符、多章节引用和原资料无答案问题。固定文档版本、chunk划分、embedding模型、查询与标注的相关片段，保存基线，再比较候选方案。Recall@k、MRR反映检索排序与覆盖，不等于引用正确，更不等于用户学习效果；引用支撑性和拒绝无依据回答另测。候选bigram/FTS/向量扩展只有在实际问题和指标收益明确时采用。

**媒体学习：**先对Reviva已有功能使用小型、来源明确的中文讲解音频/视频做验收，检查导入、转录、时间戳/关键帧、定位原片段、笔记、问答引用、取消与重试。记录ASR/provider、是否联网、费用和依赖；转录内容进入检索/复习也保留时间轴来源。未配置ASR或缺少工具时明确降级，不把云实时ASR描述为本地Whisper。若开展本地转录P2，再比较准确性、中文术语、处理时长与机器负载，不先重写已可用链路。

**首学体验：**保留旧稿“尽快进入完整学习”的目标，作为M4待测假设：在模型/网络已配置、使用内置小型样本的条件下，新用户目标10分钟内完成“选包/导入→一次问答→一次练习→看到复习条目”。首次下载安装、下载本地模型和异常排查时间单独记录，不藏在指标之外。记录完成/放弃、阻塞步骤和是否需要指导；项目发起人完成一次流程不能代表新用户均可完成，未有独立试用者时标记待验证。

命令面板、键盘快捷操作、主题和空态先盘点上游能力；先把继续学习、查看出处、提交答案、保存失败重试这些高频操作做顺，不为了增加功能数另造UI系统。专项指标分别服务检索、多模态和体验质量，不混入7.4的学习成效统计。

## 15. 风险登记与处理

| 风险 | 概率/影响（初评） | 应对与触发条件 |
|---|---|---|
| 上游授权/内置内容不清 | 中/高（分发时） | 当前个人开发继续；记录答复和来源；公开发布前解决不明确资源 |
| 上游云后台成为门禁 | 中/高 | M0验证不登录核心路径；隔离账户/积分/云产物，必要时本地适配；不承诺复刻商业后台 |
| Electron与插件升级不兼容 | 高/高 | 单独spike、原生模块和文档渲染回归；无受支持运行时方案则不发稳定版 |
| 数据丢失/迁移破坏 | 中/极高 | 临时副本、事务、迁移前备份、真实恢复演练，禁止试验原Reviva库 |
| 调度只有界面没有持久化 | 中/高 | IPC→事务→重启→推进时钟集成测试，保存失败不推进UI |
| 课程过时或许可不完整 | 高/中高 | 版本/来源台账，限制首批规模，人工审阅；每次内容发布核API示例 |
| AI误导或成本失控 | 中/高 | 固定题客观判分、引用检查、主观反馈标记、调用预算与取消 |
| 上游差异持续扩大 | 高/中高 | 模块化补丁、上游集成窗口、关键接缝回归，不整仓重构 |
| 单人范围过大 | 高/高 | 锁定一套内容和一条闭环，按阶段收缩P2/P3，不先做云同步 |
| 学习小组误导或变成AI围聊 | 中/中高（P2） | 默认关闭；用审阅误解和参考答案；等待用户但允许退出/看答案；总结校验后确认入卡，参与度不当掌握度 |
| 多角色调用拖慢或超预算 | 中/中高（P2） | 少角色、串行有限轮次、预算与取消；重开不自动续跑；无可靠收益则保持关闭 |
| 打包与真实使用不一致 | 中/高 | 开发运行和安装包分别验收，非ASCII路径、离线/缺凭据和恢复均覆盖 |

风险与缺陷跟踪由发起人维护。严重度与功能优先级分开：数据丢失、越权、无法启动、作答/调度保存错误是发布阻断；外观、小众导出等可记录后续修复，不隐瞒限制。
