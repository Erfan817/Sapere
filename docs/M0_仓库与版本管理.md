## 启动与验证命令

在项目根目录执行，Node 使用 `.node-version` 指定版本。

```bash
corepack pnpm install --frozen-lockfile
```

```bash
corepack pnpm dev --host 127.0.0.1 --strictPort
```

开发命令会启动 Vite（端口 1234）并打开 Electron 窗口。浏览器单独打开 Vite 地址没有 Electron IPC，不能代替桌面功能验收。当前 `.claude/launch.json` 提供同一开发启动入口。

只构建、不打包：

```bash
corepack pnpm run build:electron
```

业务测试（Electron 内置 Node，避免原生 ABI 不匹配）：

```bash
corepack pnpm run test:electron
```

```bash
corepack pnpm run test:wiki
```

```bash
corepack pnpm run test:skills
```

```bash
corepack pnpm run test:themes
```

模型与云依赖隔离检查（无账号、黑洞代理、占位密钥，不发起真实外部请求）：

```bash
node scripts/m0-model-cloud-check.mjs
```

真实桌面冒烟（使用已构建文件，结束时关闭测试窗口）：

```bash
node scripts/m0-desktop-smoke.mjs
```

安装后如 Electron 文件缺失，先检查 `node_modules/electron/dist/electron.exe` 和 `node_modules/electron/path.txt`；官方 npm 安装器为 `node node_modules/electron/install.js`。本机缓存/临时目录跨盘时，将其配置到工程盘，仍需核对安装器返回后文件确实存在。手动恢复只能使用与 `checksums.json` SHA-256 完全一致的对应版本/架构 ZIP，不依赖未校验镜像，不关闭完整性校验。

构建机 Node 与 Electron 内置 Node 的原生模块 ABI 不同，数据库相关测试应在 Electron 内置 Node 下运行。通过 Node 启动的 `cross-env ELECTRON_RUN_AS_NODE=1 electron --test ...` 可跨平台设置该环境变量；不要为通过测试反复重建并覆盖运行版 SQLite ABI。

## 日常版本与恢复约定

- 每完成一个可核对的小任务，就建立一个说明清楚的提交；重要可运行节点加标签。
- 功能在短期分支开发，验证后合并。共享 `main` 不强推或重写历史。
- 已共享代码出现问题时优先使用 `git revert` 新增撤销提交，保留原有历史。
- 仅恢复某个未提交文件时，先检查差异，再有针对性恢复；不默认执行 `git reset --hard` 或清空工作区。
- Git 只能恢复已保存到提交的内容。尚未提交的文件、忽略文件和本地数据库不因此获得版本保护。
- GitHub 保存的是已推送的代码历史；学习资料、应用数据库、API 密钥和工作区文件需要应用层独立备份。

## 忽略规则边界

`.gitignore` 是基础排除规则，不是密钥检测器。提交前仍需检查暂存文件，确认没有真实凭据、个人数据库或无意纳入的资源。

保留上游 `build/` 目录：它包含图标和安装器素材，不能把目录名当作生成产物全部排除。
