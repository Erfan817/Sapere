# M0 工作区与重启持久化验收

日期：2026-11-14。环境：Windows 11 x64；构建机 Node 24.16.0；Electron 30.5.1（内置 Node 20.16.0、原生 ABI 123）；pnpm 10.34.9。

## 结论

**通过：独立中文路径工作区创建、重启激活、界面编辑 Markdown 笔记、自动保存、完整关闭应用再启动后的内容恢复。**

本轮未修改应用业务代码，新增可复现的桌面验证和只读数据库检查脚本。既有构建基于提交 `0d19f14` 的源码。

## 实际流程与证据

1. 每次验证使用 `.sapere/m0-persistence/run-*` 下全新的测试目录；工作区目录名为 `中文学习工作区`，应用注册信息与浏览器会话保存在同一 run 内独立的 `user-data`。
2. 在真实 Electron 窗口点击“先设置根目录 → 选择 → 新建独立授权根目录”，输入工作区名称并确认。仅系统原生目录选择器由测试适配器返回预先创建的空目录，其余业务操作均使用界面及真实 IPC/service。
3. 核对创建后仅设置 pending 工作区；完全关闭进程，再启动后核对同一工作区变为 active，pending 清空。
4. 在笔记界面新建一篇笔记，输入中文标题、中英混合正文、emoji、列表与代码块。等待真实服务读取到完整标题/正文，核对工作区 `notes/` 中的 Markdown 文件与输入逐字一致。
5. 再次完全关闭应用并启动。三个阶段分别使用不同的进程 PID。核对工作区 ID、笔记 ID、标题、正文和相对文件路径均不变，再从笔记侧栏打开，检查编辑器恢复的值并截屏。
6. 关闭应用后以只读模式打开工作区 `.reviva/reviva.db`，检查 `PRAGMA integrity_check = ok`、`PRAGMA foreign_key_check` 无结果；笔记总数为 1，没有重复创建。核对注册文件中 active 工作区正确、pending 为空。
7. 核对 Markdown 原始字节的 SHA-256 与保存前一致：`e707b472cf3cecdf6a2b3363a4637a22493d9d5efbb9f6188427cb3dc76914d3`。页面 `pageerror` 列表为空。

数据实际结构：SQLite `notes` 表保存 ID、标题、相对文件路径等元数据，正文在 Markdown 文件中，数据库 `content` 字段为空。这是现有实现的职责划分；仅备份数据库不能覆盖笔记正文，恢复验收必须同时包含文件。

首个完整通过样本为 `.sapere/m0-persistence/run-1yWtMP/report.json`，主进程 PID 为 33992、21896、34156。原始报告与截图保留在本机忽略目录，不提交测试数据库、运行日志、截图和测试资料。

## 复现

先确保已安装依赖并完成构建；验证脚本读取构建产物，不通过 Vite 开发服务器启动。

```bash
corepack pnpm run build:electron
```

```bash
node scripts/m0-workspace-persistence.mjs
```

脚本输出 `M0_PERSISTENCE_REPORT` 给出本次 `report.json` 路径；每次创建新目录，失败时保留截图、页面文本与错误，成功或失败均关闭测试进程。

只读检查使用 Electron Node 运行时，保持 SQLite 原生 ABI 一致。将末尾报告路径换为本次输出：

```bash
corepack pnpm exec cross-env ELECTRON_RUN_AS_NODE=1 electron scripts/m0-inspect-workspace.cjs .sapere/m0-persistence/run-1yWtMP/report.json
```

桌面脚本断言失败时以非零码退出。只读检查不会创建缺失数据库，也不会修改应用数据。

## 验收边界

- 本次“重启”是完整关闭测试进程并重新启动，不是页面刷新；未点击应用内“立即重启”按钮，也未验收该按钮的自重启实现。
- 等待自动保存成功后再退出，未覆盖输入后 500ms debounce 内立即关窗、系统强制结束或断电场景。
- 只创建并验证一个测试工作区和一篇笔记；未覆盖两个工作区切换隔离、附件、目录迁移、多笔记并发写入、备份恢复和损坏恢复。
- 未配置模型、未发送付费 API 请求。测试仅声明 Windows 本机开发态通过，不代表已验证安装包或其他平台。
- 此结果推进 M0 的本地数据路径验收；Windows 打包、模型与云依赖、既有 5 项测试失败仍待处理，不能据此宣称整个 M0 已完成。
